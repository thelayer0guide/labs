Lernphilosophie
📦
Stdlib First

Jedes Lab läuft zuerst mit hashlib, socket, ssl, re, argparse, json. Keine Dependency, die du nicht verstehst.

🔪
Logik von I/O trennen

Kernfunktionen ohne print() oder Dateizugriff. Macht spätere Tests und Integration in uctl trivial.

📱
uConsole-Realität

ARM64, kleines Terminal (~80 Spalten), oft offline. Keine Busy-Loops, schlanke Dependencies, Terminal-Breite dynamisch erkennen.

🔗
Plugin-Ready von Anfang an

Jedes Tool bekommt eine Schnittstelle, die 1:1 ein uctl-Subcommand wird. Phase 6 fügt alles zusammen.

LAB 00

Projekt-Skeleton & Dev-Workflow

❯ mkdir security-lab && cd security-lab
❯ poetry init && poetry add --dev pytest ruff black
Aufgabe
  • Mono-Repo mit einem Unterordner pro Tool (je core.py, cli.py, tests/)
  • shared/ für spätere gemeinsame Utils (Logging, Output-Formatting)
  • pyproject.toml mit pytest, black, ruff als Dev-Dependencies
  • Makefile / justfile mit test, lint, format
  • Sinnvolles .gitignore (pycache, .venv, *.egg-info)
Gelernt
poetry pyproject.toml pytest-Grundgerüst Git-Workflow Projektstruktur

Phase 1

Daten & Dateien

hashlib · Bytes/Strings · Statistik · CSV-Export
LAB 01

Hash Inspector

❯ hashinspect kali.iso --check hashes.txt
SHA256 ✓ 3.8 GB · 4.2s
Pflicht
  • SHA256, SHA1, MD5 berechnen
  • Dateien in Blöcken lesen (kein komplett-in-RAM — wichtig bei ISO-Dateien)
  • Vergleich gegen --check hashes.txt (Format wie sha256sum)
  • Exit-Code 0/1 für Skript-Verkettung
  • Eigene Fortschrittsanzeige mit \r + sys.stdout.write
Bonus
  • --algo sha256 zur Auswahl einzelner Algorithmen
  • Mehrere Dateien parallel verarbeiten
Gelernt
hashlib chunked I/O argparse Exit-Codes Fortschrittsanzeige
Schnittstelle für später:
def hash_file(path: Path, algos: list[str]) -> dict[str, str]
Diese Signatur wird 1:1 ein uctl hash-Subcommand.
LAB 02

Base Encoding Toolkit

❯ enc decode "SGVsbG8="
Hello
❯ enc encode --format hex -f file.bin
Pflicht
  • encode/decode für Base64, Base32, Hex, URL-Encoding
  • String-Modus und Datei-Modus (-f)
  • Sinnvolle Fehlermeldung bei ungültigem Input (fehlerhaftes Padding)
Bonus
  • Auto-Erkennung des Encodings bei decode (Zeichensatz-Heuristik)
  • --chain base64,hex für mehrfaches Encoding in einer Pipeline
Gelernt
base64 urllib.parse Bytes vs Strings pytest parametrize
Test-Highlight: Hier ist die Logik reine Transformation — idealer Einstieg in @pytest.mark.parametrize mit vielen Input/Output-Paaren.
LAB 03

Entropy Scanner

❯ entropy ~/Downloads --threshold 7.5
SUSPECT payload.bin 7.94
OK readme.txt 3.21
Pflicht
  • Shannon-Entropie pro Datei: -Σ p·log2(p) auf Byte-Häufigkeiten
  • Rekursiver Verzeichnisscan mit Filter (--ext, --min-size)
  • Schwellenwert-Markierung (>7.5 bit/byte = "verdächtig")
  • CSV-Report (pfad, größe, entropie, flag)
Bonus
  • Byte-Verteilung als ASCII-Balkendiagramm im Terminal
  • Kombination mit Dateityp/Extension im Report
Gelernt
Shannon-Entropie pathlib.rglob csv Statistik
Forensischer Kontext: Hohe Entropie ≠ Malware. Backups, Crypto-Container und Mediendateien sind genauso hoch-entropisch. Report immer mit Dateityp kombinieren — schult sauberes Findings vs. Interpretation-Denken.
Phase 2

Parsing & Forensik

Regex · Datenmodelle · Rekursion · Metadaten
LAB 04

Log Forensics Toolkit

❯ logaudit auth.log --since "2026-06-01"
Top-IP: 185.220.101.x · 1842 Versuche
Pflicht
  • IP-Adressen extrahieren (IPv4 + IPv6) via Regex-Gruppen
  • Fehlgeschlagene SSH-Logins zählen, nach IP gruppiert + sortiert
  • Zeitraum-Filter (--since, --until)
  • Zusammenfassung: Top-10-IPs, Stunden-Histogramm, Login-Erfolgsquote
  • --format json für maschinenlesbaren Output
Bonus
  • GeoIP-Lookup via lokaler MaxMind-DB (offline)
  • nginx-Logs zusätzlich zu auth.log parsen
Gelernt
Regex-Gruppen datetime-Parsing Counter dataclass
Architektur-Muster: Hier einführen: Parser → Datenmodell (dataclass LogEntry) → Aggregation → Report. Dieses Muster zieht sich durch fast alle folgenden Labs.
LAB 05

Metadata Extractor

❯ meta foto.jpg --format json
GPS 48.1351° N, 11.5820° E
Camera iPhone 15 Pro Max
Pflicht
  • EXIF-Daten aus JPEG/PNG (Kamera, GPS, Aufnahmedatum)
  • PDF-Metadaten (Autor, Erstellungstool, Änderungsdatum, Seitenanzahl)
  • Generische Dateieigenschaften via os.stat
  • Einheitlicher JSON-Export, unabhängig vom Dateityp
Bonus
  • Warnung bei verdächtigen Diskrepanzen (PDF "erstellt" nach "geändert")
  • GPS-Koordinaten aus EXIF in Dezimalgrad umrechnen
Gelernt
Pillow pypdf EXIF os.stat Datenstrukturen
Datenschutz-Mindset: Dieses Tool zeigt, wie viel Metadaten man unabsichtlich weitergibt. Guter Use-Case: auf eigene Dateien anwenden, bevor man sie teilt.
LAB 06

Secret Detector

❯ secretaudit ~/projects --format md
[HIGH] .env:12 AWS_ACCESS_KEY_ID
AKIA***...***4F3
Pflicht
  • Pattern: generische API-Keys, AWS (AKIA[0-9A-Z]{16}), Private Keys, JWTs, password=
  • Ausschluss von node_modules, .git, venv
  • Severity-Einstufung: High / Medium / Low je Pattern
  • Secrets im Report immer maskieren (erste + letzte 4 Zeichen)
  • Markdown-Report mit Datei, Zeile, Pattern-Typ, Context-Snippet
Bonus
  • Entropie-Check (Lab 03) als zweites Signal kombinieren
  • .secretauditignore für bekannte False Positives
Gelernt
Regex-Pattern Severity-Modelle rekursive Suche Security Auditing
Wichtig: Dieses Tool maskiert gefundene Secrets immer im Report. Es ist ein Auditing-Tool, kein Exfiltrations-Tool.
Phase 3

Krypto & Netzwerk

sockets · ssl · psutil · Entropie-Theorie
LAB 07

Certificate Auditor

❯ certaudit github.com
Issuer DigiCert TLS RSA SHA256
⚠ Läuft ab in 28 Tagen
Pflicht
  • TLS-Verbindung aufbauen, Zertifikat auslesen (ssl + cryptography.x509)
  • Issuer, Subject, Gültigkeitszeitraum, SAN-Einträge anzeigen
  • Warnung bei <30 Tagen Restlaufzeit (konfigurierbarer Schwellenwert)
  • Zertifikatskette anzeigen (Anzahl Zwischenzertifikate)
Bonus
  • Batch-Modus: Host-Liste aus Datei, Sammelreport
  • Schwache Signaturalgorithmen flaggen (z. B. SHA1)
Gelernt
socket ssl X.509 datetime cryptography
Ideal für eigene Heimnetz-Zertifikate (Router, NAS, selbst gehostete Dienste) — auch offline gegen lokale IPs prüfbar.
LAB 08

Password Strength Analyzer

❯ pwcheck "Tr0ub4dor&3"
Stärke Gut · 72.3 bit
Crack ~147 Jahre @ 10^9/s
Pflicht
  • Zeichenklassen erkennen (Klein/Groß, Ziffern, Sonderzeichen)
  • Entropie in Bit berechnen (Zeichenraum × Länge)
  • Abgleich gegen lokale Liste häufiger Passwörter (rockyou-Auszug, offline)
  • Verständlicher Bericht inkl. geschätzter Crack-Zeit bei definierten Angriffsraten
Bonus
  • Tastatur-Mustererkennung (qwertz123, asdf)
  • HaveIBeenPwned-API via k-Anonymity (Klartext verlässt das Gerät nie)
Gelernt
Entropie-Theorie Regex String-Verarbeitung Privacy-Design
Privacy-Hinweis: Reine lokale Bewertung — kein Versand von Klartextpasswörtern. Die k-Anonymity-Integration ist ein Lehrbeispiel für privacy-bewusstes API-Design.
LAB 09

Local Port Inventory

❯ portinv --proto tcp --format json

Bonus

Process & Service Baseline Monitor

Pflicht

Offline PCAP Analyzer

Pflicht

// Unified Security Toolkit — Endprojekt

uctl — alles in einem

Alle 18 Labs werden zu einer einzigen CLI-Suite vereint. Jedes Tool wird zum Plugin. Eine gemeinsame Config, ein gemeinsames Logging, ein gemeinsames Output-Format. Installierbar via pipx install . — auch offline auf der uConsole.

CLI-Framework
  • Typer ersetzt alle bisherigen argparse-Subcommands
  • Zentrale ~/.config/uctl/config.toml für Defaults (Schwellenwerte, Ausschlusspfade)
  • Zentrales Logging (logging-Modul, --verbose/--quiet)
Output & Integration
  • Einheitliches Format über alle Subcommands via rich
  • --json für Skriptverkettung bei jedem Command
  • Terminal-Breite dynamisch: shutil.get_terminal_size()
  • Online-Tools explizit markiert (Cert, CVE)
Packaging & Deployment
  • pipx install . — funktioniert offline nach Wheel-Cache
  • Plugin-Discovery via entry_points (Lab 17)
  • Unit-Tests für alle Kernmodule (Lab 16)
  • Kein Polling ohne expliziten --watch-Flag
