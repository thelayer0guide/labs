Virtuelle Maschinen & Container

Cheat Sheets

Lernziele
  • Unterschied VM vs. Container erklären
  • Docker-Container erstellen, starten und verwalten
  • Dockerfile für eigene Images schreiben
  • Ressourcenisolation und Sicherheitsimplikationen verstehen
Hintergrund

Virtuelle Maschinen (VMs) emulieren vollständige Hardware inklusive eigenem Betriebssystem. Hypervisor Typ 1 (bare-metal: VMware ESXi, KVM) läuft direkt auf Hardware. Hypervisor Typ 2 (hosted: VirtualBox, VMware Workstation) läuft auf Host-OS. VMs bieten starke Isolation aber hohen Overhead. Container (Docker, Podman) teilen den Host-Kernel — kein eigenes OS. Leichter, schneller, weniger Overhead, aber schwächere Isolation.

Docker-Architektur: Docker Daemon läuft auf dem Host. Docker Client sendet Befehle. Registry (Docker Hub) speichert Images. Image: schreibgeschützte Vorlage (Schichten). Container: laufende Instanz eines Images. Volumes: persistenter Speicher außerhalb des Containers. Networks: Isolation und Kommunikation zwischen Containern. Im Security-Kontext: Container-Escape-Vulnerabilities, privilegierte Container, gemountete Host-Sockets sind häufige Angriffsvektoren.

Schlüsselkonzepte

Docker Grundlagen

Code anzeigen
# Docker-Installation prüfen
docker --version
docker info

# Container starten
docker run hello-world
docker run -it ubuntu bash    # Interaktiv
docker run -d -p 8080:80 nginx  # Detached, Port-Mapping

# Container verwalten
docker ps                     # Laufende Container
docker ps -a                  # Alle Container
docker stop               # Stoppen
docker rm                 # Entfernen
docker logs               # Logs anzeigen

# Images
docker images                 # Lokale Images
docker pull python:3.12       # Image herunterladen
docker rmi             # Image entfernen

# Dockerfile
# FROM python:3.12-slim
# WORKDIR /app
# COPY requirements.txt .
# RUN pip install -r requirements.txt
# COPY . .
# CMD ["python", "app.py"]

docker build -t meine-app:1.0 .
docker run -p 5000:5000 meine-app:1.0
Aufgabe

Erstelle ein Dockerfile für eine Python-Flask-Anwendung, baue das Image und starte einen Container. Prüfe mit docker inspect die Konfiguration.

Anforderungen
  1. VM vs. Container: Isolation, Overhead, Startup-Zeit vergleichen
  2. Docker: Image, Container, Volume, Network erklären
  3. Dockerfile mit FROM, RUN, COPY, CMD schreiben
  4. docker build und docker run ausführen
  5. Container-Security: privilegierter Container und Socket-Mount als Risiko
Akzeptanzkriterien
  • Dockerfile korrekt geschrieben
  • Container gestartet und zugänglich
  • docker inspect-Ausgabe erklärt
