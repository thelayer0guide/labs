Hintergrund

Eine VPC ist ein logisch isoliertes Netzwerk in der Cloud — vergleichbar mit einem eigenen Rechenzentrum. Innerhalb einer VPC: Subnets (Teilnetzwerke) in verschiedenen Availability Zones (AZ). Public Subnet: hat Route zum Internet Gateway (für öffentlich zugängliche Ressourcen). Private Subnet: kein direkter Internet-Zugang (für Datenbanken, Backend). NAT Gateway: ermöglicht Outbound-Internet für private Subnets.

Security Groups sind zustandsbehaftete (Stateful) Firewalls auf Instanz-Ebene: Inbound Rules definieren erlaubten eingehenden Traffic, Outbound wird automatisch erlaubt. NACLs (Network ACLs) sind zustandslose (Stateless) Firewalls auf Subnet-Ebene: Inbound und Outbound müssen separat konfiguriert werden. Im Security-Kontext: Security Groups mit 0.0.0.0/0 auf Port 22 oder 3389 sind ein häufiges Risiko. VPC Flow Logs für Netzwerk-Forensik.

Schlüsselkonzepte

VPC & Security Groups

Code anzeigen
# VPC-Überblick
aws ec2 describe-vpcs
aws ec2 describe-subnets
aws ec2 describe-internet-gateways
aws ec2 describe-route-tables

# Security Groups
aws ec2 describe-security-groups
aws ec2 describe-security-groups \
  --filters "Name=ip-permission.cidr,Values=0.0.0.0/0"

# Security Group erstellen
aws ec2 create-security-group \
  --group-name "web-sg" \
  --description "Web-Server Security Group" \
  --vpc-id vpc-xxxxx

# SSH nur von eigener IP erlauben
aws ec2 authorize-security-group-ingress \
  --group-id sg-xxxxx \
  --protocol tcp --port 22 \
  --cidr $(curl -s ifconfig.me)/32

# VPC Flow Logs aktivieren
aws ec2 create-flow-logs \
  --resource-type VPC \
  --resource-ids vpc-xxxxx \
  --traffic-type ALL \
  --log-destination-type cloud-watch-logs \
  --log-group-name /vpc/flowlogs
