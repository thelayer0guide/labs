Compliance-Checks & Reporting

Cheat Sheets
linux
Lernziele
  • Das assert-Modul für Compliance-Prüfungen einsetzen
  • Einen strukturierten Compliance-Report als JSON/CSV exportieren
  • Callback-Plugins für angepassten Output konfigurieren
  • Soll/Ist-Vergleiche mit stat, command und set_fact aufbauen
Hintergrund

Compliance-Playbooks prüfen ob ein System den definierten Standards entspricht, ohne Änderungen vorzunehmen. Das assert-Modul schlägt fehl wenn eine Bedingung nicht erfüllt ist: assert: that: "ansible_memtotal_mb >= 2048" fail_msg: "Zu wenig RAM". Mit ignore_errors: true und register können alle Checks gesammelt und am Ende als Report ausgegeben werden.

Für Enterprise-Reporting: Ergebnisse in eine Variable accumulate (set_fact, list append), am Ende mit copy oder template als JSON/CSV auf den Control Node schreiben. Callback-Plugins ändern die Ausgabe von ansible-playbook: yaml (besser lesbar), json (maschinenlesbar), junit (für CI/CD), oder ein eigenes Plugin. ANSIBLE_STDOUT_CALLBACK=yaml ansible-playbook site.yml.

Schlüsselkonzepte

Compliance-Check-Playbook

Code anzeigen
---
# compliance_check.yml
- name: CIS Compliance Check
  hosts: all
  gather_facts: true
  vars:
    checks: []         # Ergebnis-Akkumulator
    min_ram_mb: 2048
    max_login_grace: 60

  tasks:
    - name: RAM prüfen
      block:
        - assert:
            that: "ansible_memtotal_mb >= {{ min_ram_mb }}"
            fail_msg: "RAM {{ ansible_memtotal_mb }}MB < {{ min_ram_mb }}MB (FAIL)"
            success_msg: "RAM {{ ansible_memtotal_mb }}MB >= {{ min_ram_mb }}MB (PASS)"
      rescue:
        - set_fact:
            checks: "{{ checks + [{
              'check': 'RAM-Minimum',
              'status': 'FAIL',
              'actual': ansible_memtotal_mb | string + 'MB',
              'expected': min_ram_mb | string + 'MB'
            }] }}"
      always:
        - set_fact:
            checks: "{{ checks + [{
              'check': 'RAM-Minimum',
              'status': 'PASS' if ansible_memtotal_mb >= min_ram_mb else 'FAIL',
              'actual': ansible_memtotal_mb | string + 'MB',
              'expected': '>=' + min_ram_mb | string + 'MB'
            }] }}"

    - name: SSH-Parameter prüfen
      command: "sshd -T"
      register: sshd_config
      changed_when: false
      failed_when: false

    - name: SSH PermitRootLogin Check
      set_fact:
        checks: "{{ checks + [{
          'check': 'SSH-PermitRootLogin',
          'status': 'PASS' if 'permitrootlogin no' in sshd_config.stdout else 'FAIL',
          'actual': (sshd_config.stdout | regex_search('permitrootlogin \\S+')) | default('nicht gesetzt'),
          'expected': 'permitrootlogin no'
        }] }}"

    - name: Passwort-Lockout prüfen
      stat:
        path: /etc/security/faillock.conf
      register: faillock

    - name: Faillock-Check
      set_fact:
        checks: "{{ checks + [{
          'check': 'PAM-Faillock',
          'status': 'PASS' if faillock.stat.exists else 'FAIL',
          'actual': 'vorhanden' if faillock.stat.exists else 'fehlt',
          'expected': 'vorhanden'
        }] }}"

    - name: Compliance-Zusammenfassung ausgeben
      debug:
        msg: "{{ item.check }}: {{ item.status }} (ist={{ item.actual }}, soll={{ item.expected }})"
      loop: "{{ checks }}"
      loop_control:
        label: "{{ item.check }}"

    - name: Report als JSON exportieren
      copy:
        content: "{{ {
          'host': inventory_hostname,
          'timestamp': ansible_date_time.iso8601,
          'checks': checks,
          'summary': {
            'total': checks | length,
            'passed': checks | selectattr('status', 'eq', 'PASS') | list | length,
            'failed': checks | selectattr('status', 'eq', 'FAIL') | list | length
          }
        } | to_nice_json }}"
        dest: "/tmp/compliance_{{ inventory_hostname }}.json"
      delegate_to: localhost

delegate_to: localhost schreibt die Datei auf den Control Node, nicht auf den Target-Host.

Aufgabe

Erstelle ein Compliance-Check-Playbook mit 8+ Prüfungen (RAM, SSH, sysctl, Dienste, Dateiberechtigungen). Exportiere einen JSON-Report pro Host auf den Control Node.

Anforderungen
  1. assert-Modul mit fail_msg und success_msg für mind. 3 Checks
  2. block/rescue/always-Struktur für fehlertolerante Checks
  3. set_fact: checks-Akkumulator mit Liste aller Ergebnisse
  4. sshd -T für dynamische SSH-Konfiguration genutzt
  5. stat für Datei-Existenz-Checks
  6. delegate_to: localhost für Report auf Control Node
  7. to_nice_json Filter für lesbaren Output
Akzeptanzkriterien
  • Report enthält alle Checks mit PASS/FAIL
  • Playbook bricht nicht bei einzelnen FAIL-Checks ab
  • JSON-Report ist valide und vollständig
