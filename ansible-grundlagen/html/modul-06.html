Ansible Vault & Secrets-Management

Cheat Sheets
linux
Lernziele
  • Dateien und einzelne Werte mit ansible-vault verschlüsseln
  • Vault-IDs für verschiedene Umgebungen (dev/prod) einsetzen
  • Secrets sicher in Playbooks verwenden ohne Klartext im Code
  • Vault in CI/CD-Pipelines mit Vault-Password-Files integrieren
Hintergrund

Ansible Vault verschlüsselt sensitive Daten mit AES-256. Verschlüsselte Dateien können in Git eingecheckt werden — ohne das Passwort sind sie unlesbar. ansible-vault encrypt datei.yml verschlüsselt eine ganze Datei. ansible-vault encrypt_string "geheim" gibt einen inline-verschlüsselten String zurück, der direkt in YAML-Variablen eingebettet werden kann.

Vault-IDs ermöglichen mehrere Passwörter für verschiedene Umgebungen: --vault-id dev@prompt, --vault-id prod@~/.vault_prod. Beim Entschlüsseln probiert Ansible alle bekannten Vault-IDs. Für CI/CD: Passwort in einer Datei (.vault_password) die nicht in Git liegt (in .gitignore), dann ansible-playbook site.yml --vault-password-file .vault_password. In GitHub Actions: Secret als Umgebungsvariable, ansible-vault mit ANSIBLE_VAULT_PASSWORD_FILE.

Schlüsselkonzepte

Vault-Befehle & inline-Secrets

Code anzeigen
# Neue verschlüsselte Datei erstellen
ansible-vault create group_vars/all/vault.yml

# Existierende Datei verschlüsseln
ansible-vault encrypt group_vars/production/secrets.yml

# Einzelnen Wert verschlüsseln (inline)
ansible-vault encrypt_string "S3cur3P@ssw0rd" --name "db_password"
# Ausgabe (in YAML einfügen):
# db_password: !vault |
#   $ANSIBLE_VAULT;1.1;AES256
#   3636363636...

# Datei anzeigen/editieren
ansible-vault view group_vars/all/vault.yml
ansible-vault edit group_vars/all/vault.yml

# Passwort ändern
ansible-vault rekey secrets.yml

# Playbook mit Vault ausführen
ansible-playbook site.yml --ask-vault-pass
ansible-playbook site.yml --vault-password-file .vault_password

# Vault-ID für mehrere Umgebungen
ansible-vault encrypt --vault-id dev@prompt dev_secrets.yml
ansible-vault encrypt --vault-id prod@~/.vault_prod prod_secrets.yml
ansible-playbook site.yml \
  --vault-id dev@.vault_dev \
  --vault-id prod@.vault_prod

Vault-Struktur in Projekten

Code anzeigen
# Empfohlene Verzeichnisstruktur
group_vars/
├── all/
│   ├── vars.yml        # Klartextvariablen
│   └── vault.yml       # Verschlüsselt — in Git
group_vars/
├── production/
│   ├── vars.yml        # z.B. db_host: prod-db.example.com
│   └── vault.yml       # z.B. vault_db_password: ...

# group_vars/all/vars.yml — Klartext-Referenz
db_password: "{{ vault_db_password }}"   # Referenz auf Vault-Variable
api_key:     "{{ vault_api_key }}"

# group_vars/all/vault.yml — verschlüsselt
vault_db_password: !vault |
  $ANSIBLE_VAULT;1.1;AES256
  ...
vault_api_key: !vault |
  $ANSIBLE_VAULT;1.1;AES256
  ...

# .gitignore
.vault_password
*.vault_password
# NICHT ignorieren:
# group_vars/*/vault.yml  — diese sollen in Git!

# CI/CD (GitHub Actions)
# - name: Vault-Passwort schreiben
#   run: echo "${{ secrets.VAULT_PASSWORD }}" > .vault_password
# - name: Playbook ausführen
#   run: ansible-playbook site.yml --vault-password-file .vault_password

Das Muster vars.yml + vault.yml trennt Struktur von Secrets. Nur vault.yml ist verschlüsselt, vars.yml zeigt welche Variablen existieren — lesbar ohne Passwort.

Aufgabe

Erstelle eine vault.yml mit 3 verschlüsselten Secrets (DB-Passwort, API-Key, SSH-Passphrase). Binde sie per vars.yml-Referenz in ein Playbook ein. Dokumentiere den CI/CD-Workflow.

Anforderungen
  1. ansible-vault create und encrypt verwendet
  2. vault.yml: mind. 3 Secrets verschlüsselt
  3. vars.yml: Referenz-Pattern "{{ vault_* }}"
  4. .vault_password in .gitignore
  5. ansible-playbook --vault-password-file funktioniert
  6. Vault-Passwort nie im Klartext in Code oder Logs
Akzeptanzkriterien
  • Playbook läuft ohne --ask-vault-pass mit .vault_password-File
  • Secrets erscheinen nie im ansible-playbook Output
  • vault.yml ist in Git eingecheckt aber unlesbar ohne Passwort
