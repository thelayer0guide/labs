Systemhärtung & CIS-Benchmark

Cheat Sheets
linux
Lernziele
  • SSH-Dämon nach CIS-Richtlinien härtend konfigurieren
  • Kernel-Härtungsparameter über sysctl deployen
  • PAM-Passwortrichtlinien und Account-Lockout konfigurieren
  • auditd für Sicherheits-Logging aktivieren und regeln
Hintergrund

CIS (Center for Internet Security) Benchmarks sind branchenstandard-Härtungsrichtlinien für OS, Middleware und Cloud. Level 1 = wichtige Maßnahmen ohne Funktionseinschränkung. Level 2 = tiefe Härtung, evtl. Einschränkungen. Für Ubuntu 22.04 LTS gibt es den CIS Benchmark Ubuntu Linux 22.04 LTS. Ansible-Rollen wie dev-sec.os-hardening implementieren viele dieser Maßnahmen automatisiert.

SSH-Härtung: Schlüssel-Authentifizierung erzwingen, Root-Login verbieten, leere Passwörter verbieten, Algorithmen einschränken, LoginGraceTime reduzieren. sysctl-Härtung: IP-Forwarding deaktivieren (außer Router), SYN-Cookies aktivieren, ICMP-Redirects deaktivieren, Kernel-Pointer verbergen. PAM: pam_pwquality für Passwort-Komplexität, pam_tally2 oder pam_faillock für Account-Lockout nach N Fehlversuchen.

Schlüsselkonzepte

SSH-Härtung

Code anzeigen
---
# roles/hardening/tasks/ssh.yml
- name: SSH-Konfiguration härten
  lineinfile:
    path: /etc/ssh/sshd_config
    regexp: "^#?{{ item.key }}"
    line: "{{ item.key }} {{ item.value }}"
    state: present
    validate: "sshd -t -f %s"
  loop:
    - { key: "PermitRootLogin",          value: "no" }
    - { key: "PasswordAuthentication",   value: "no" }
    - { key: "PermitEmptyPasswords",     value: "no" }
    - { key: "X11Forwarding",            value: "no" }
    - { key: "LoginGraceTime",           value: "30" }
    - { key: "MaxAuthTries",             value: "3" }
    - { key: "MaxSessions",              value: "4" }
    - { key: "ClientAliveInterval",      value: "300" }
    - { key: "ClientAliveCountMax",      value: "2" }
    - { key: "Protocol",                 value: "2" }
    - { key: "IgnoreRhosts",             value: "yes" }
    - { key: "HostbasedAuthentication",  value: "no" }
    - { key: "UsePAM",                   value: "yes" }
    - { key: "AllowAgentForwarding",     value: "no" }
    - { key: "AllowTcpForwarding",       value: "no" }
  notify: sshd restart
  tags: [ssh, hardening]

- name: Erlaubte Krypto-Algorithmen setzen
  blockinfile:
    path: /etc/ssh/sshd_config
    marker: "# {mark} ANSIBLE MANAGED — KRYPTO"
    block: |
      KexAlgorithms curve25519-sha256,diffie-hellman-group14-sha256
      Ciphers aes256-gcm@openssh.com,aes128-gcm@openssh.com
      MACs hmac-sha2-512,hmac-sha2-256
      HostKeyAlgorithms ssh-ed25519,rsa-sha2-512
  notify: sshd restart
  tags: [ssh, hardening, crypto]

Kernel & auditd

Code anzeigen
---
# roles/hardening/tasks/kernel.yml
- name: Kernel-Härtungsparameter setzen
  sysctl:
    name: "{{ item.key }}"
    value: "{{ item.value }}"
    state: present
    sysctl_set: true
    reload: true
  loop:
    # Netzwerk-Härtung
    - { key: "net.ipv4.ip_forward",                  value: "0" }   # Kein IP-Forwarding
    - { key: "net.ipv4.conf.all.accept_redirects",   value: "0" }   # Keine ICMP-Redirects
    - { key: "net.ipv4.conf.all.send_redirects",     value: "0" }
    - { key: "net.ipv4.conf.all.rp_filter",          value: "1" }   # Reverse-Path-Filter
    - { key: "net.ipv4.tcp_syncookies",              value: "1" }   # SYN-Flood-Schutz
    - { key: "net.ipv4.conf.all.log_martians",       value: "1" }   # Martian packets loggen
    # Kernel-Härtung
    - { key: "kernel.randomize_va_space",             value: "2" }   # ASLR
    - { key: "kernel.dmesg_restrict",                 value: "1" }   # dmesg nur root
    - { key: "kernel.kptr_restrict",                  value: "2" }   # Kernel-Pointer verbergen
    - { key: "fs.protected_hardlinks",                value: "1" }
    - { key: "fs.protected_symlinks",                 value: "1" }
  tags: [kernel, hardening, sysctl]

- name: auditd installieren und konfigurieren
  apt:
    name: [auditd, audispd-plugins]
    state: present

- name: Audit-Regeln deployen
  copy:
    dest: /etc/audit/rules.d/hardening.rules
    content: |
      # Privilegierte Befehle loggen
      -a always,exit -F arch=b64 -S execve -F euid=0 -k root_commands
      # sudo/su überwachen
      -w /bin/su -p x -k su_usage
      -w /usr/bin/sudo -p x -k sudo_usage
      # SSH-Konfiguration überwachen
      -w /etc/ssh/sshd_config -p wa -k sshd_config
      # Passwort-Dateien überwachen
      -w /etc/passwd -p wa -k passwd_changes
      -w /etc/shadow -p wa -k shadow_changes
      -w /etc/sudoers -p wa -k sudoers_changes
  notify: auditd reload
  tags: [auditd, hardening]

sysctl_set: true schreibt den Wert sofort in den laufenden Kernel — reload: true schreibt ihn in die sysctl.conf für Persistenz.

Aufgabe

Erstelle eine Hardening-Rolle mit SSH-, Kernel- und auditd-Tasks. Alle Maßnahmen als Tags markiert. Playbook läuft im --check-Modus ohne Fehler.

Anforderungen
  1. SSH: mind. 12 Parameter mit lineinfile korrekt gesetzt
  2. blockinfile für Krypto-Algorithmen korrekt
  3. sysctl: mind. 8 Kernel-Parameter mit sysctl-Modul
  4. auditd: Regeln für passwd, shadow, sudo, ssh
  5. validate: "sshd -t -f %s" im lineinfile-Task
  6. Tags: ssh, kernel, auditd, hardening
  7. --check-Modus zeigt erwartete Änderungen
Akzeptanzkriterien
  • Alle SSH-Parameter in sshd_config korrekt gesetzt
  • sysctl -a zeigt neue Werte
  • auditd läuft und Regeln sind geladen
