Idempotenz, Tags & Check-Mode

Cheat Sheets
linux
Lernziele
  • Das Idempotenz-Prinzip verstehen und aktiv sicherstellen
  • changed_when und failed_when für Custom-Logic einsetzen
  • Tags für selektive Task-Ausführung vergeben
  • Check-Mode (Dry-run) und Diff-Mode für sichere Änderungen nutzen
Hintergrund

Idempotenz bedeutet: ein Playbook mehrfach ausführen → immer dasselbe Ergebnis, keine unerwarteten Seiteneffekte. Die meisten Ansible-Module sind automatisch idempotent. command und shell sind es nicht — sie laufen immer. Lösungen: creates=/pfad (überspringen wenn Datei existiert), registers + when, oder das stat-Modul um Zustände zu prüfen.

changed_when: false sagt Ansible, dass ein Task nie als "geändert" gilt — gut für reine Lesebefehle. changed_when: result.stdout != "" setzt changed dynamisch. failed_when: result.rc != 0 and "Not found" not in result.stderr erlaubt differenziertere Fehlerbehandlung als der default (rc != 0). Tags ermöglichen ansible-playbook --tags install oder --skip-tags debug um selektiv Teile auszuführen.

Schlüsselkonzepte

Idempotenz für command/shell

Code anzeigen
---
- name: Idempotente command-Tasks
  hosts: all
  become: true

  tasks:
    # SCHLECHT: läuft immer, immer "changed"
    # - command: useradd deploy

    # GUT: Variante 1 — creates (überspringt wenn Datei existiert)
    - name: Zertifikat erstellen (einmalig)
      command: openssl req -x509 -newkey rsa:4096 -keyout /etc/ssl/key.pem -out /etc/ssl/cert.pem -days 365 -nodes -subj "/CN=localhost"
      args:
        creates: /etc/ssl/cert.pem   # Überspringen wenn schon da

    # GUT: Variante 2 — stat + when
    - name: App-Status prüfen
      stat:
        path: /opt/myapp/current
      register: app_installed

    - name: App nur installieren wenn noch nicht vorhanden
      unarchive:
        src: myapp-1.0.tar.gz
        dest: /opt/myapp/
      when: not app_installed.stat.exists

    # GUT: Variante 3 — changed_when mit Vergleich
    - name: Aktuelle Version prüfen
      command: myapp --version
      register: current_version
      changed_when: current_version.stdout != "1.0.0"
      failed_when: current_version.rc != 0 and current_version.rc != 127

    # Kein changed bei Lese-Befehlen
    - name: Systeminfo sammeln
      command: uname -r
      register: kernel_version
      changed_when: false
      failed_when: false

    - name: Kernel-Version ausgeben
      debug:
        msg: "Kernel: {{ kernel_version.stdout }}"

Tags & Check-Mode

Code anzeigen
---
- name: Playbook mit Tags
  hosts: all
  become: true

  tasks:
    - name: Pakete installieren
      apt:
        name: [nginx, curl, git]
        state: present
      tags:
        - install
        - packages
        - never   # nur mit --tags never ausführen

    - name: Konfiguration deployen
      template:
        src: nginx.conf.j2
        dest: /etc/nginx/nginx.conf
      tags: [config, nginx]
      notify: nginx reload

    - name: Service starten
      service:
        name: nginx
        state: started
      tags: [service, nginx]

    - name: Debug-Info (nur explizit)
      debug:
        var: ansible_facts
      tags: [debug, never]

# Nutzung:
# ansible-playbook site.yml --tags install
# ansible-playbook site.yml --tags nginx
# ansible-playbook site.yml --skip-tags debug
# ansible-playbook site.yml --list-tags

# Check-Mode (Dry-run) — keine echten Änderungen
# ansible-playbook site.yml --check
# ansible-playbook site.yml --check --diff    # Zeigt Datei-Diffs

# Task nur im Check-Mode:
# check_mode: false  # Immer ausführen, auch in --check
# check_mode: true   # Nur im Check-Mode ausführen

tag: never ist speziell — dieser Task läuft niemals automatisch, nur wenn explizit mit --tags never oder dem Tag-Namen aufgerufen.

Aufgabe

Auditiere ein bestehendes Playbook auf Idempotenz: identifiziere nicht-idempotente Tasks und mache sie idempotent. Füge ein vollständiges Tag-System hinzu.

Anforderungen
  1. command/shell ohne creates/when als nicht-idempotent identifiziert
  2. stat + when als Lösung für mindestens 2 Tasks
  3. changed_when: false bei allen Lese-Tasks
  4. failed_when mit differenzierter Bedingung
  5. Tags: install, config, service, debug, never
  6. --check --diff Ausführung ohne Fehler dokumentiert
Akzeptanzkriterien
  • Playbook läuft 3x ohne Änderungen (idempotent)
  • Tags funktionieren selektiv
  • --check meldet keine false positives
