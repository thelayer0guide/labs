Facts, Magic Variables & Custom Facts

Cheat Sheets
linux
Lernziele
  • Ansible-Facts verstehen und im Playbook gezielt abfragen
  • Das setup-Modul und gather_facts: false korrekt einsetzen
  • Magic Variables wie hostvars, groups und inventory_hostname nutzen
  • Custom Facts in /etc/ansible/facts.d hinterlegen
Hintergrund

Facts sind automatisch gesammelte Informationen über das Zielsystem: OS-Familie, IP-Adressen, CPU-Anzahl, freier Speicher, Netzwerk-Interfaces, gemountete Dateisysteme. Sie werden durch gather_facts: true (default) zu Beginn jedes Plays gesammelt. Zugriff: ansible_facts["os_family"] oder kurz ansible_os_family (in ansible.cfg: inject_facts_as_vars = true).

Magic Variables sind durch Ansible selbst gesetzt: inventory_hostname (Name im Inventory), ansible_host (IP/Hostname für SSH), groups["webserver"] (Liste aller Hosts in der Gruppe), hostvars["web02"]["ansible_host"] (Facts/Vars eines anderen Hosts). Custom Facts: Dateien in /etc/ansible/facts.d/*.fact (Shell-Script oder JSON) werden automatisch geladen in ansible_local.dateiname.schluessel.

Schlüsselkonzepte

Facts nutzen

Code anzeigen
---
- name: Facts nutzen und anzeigen
  hosts: all
  gather_facts: true

  tasks:
    - name: Wichtige System-Facts
      debug:
        msg:
          - "Hostname:      {{ ansible_hostname }}"
          - "OS-Familie:    {{ ansible_os_family }}"
          - "Distribution:  {{ ansible_distribution }} {{ ansible_distribution_version }}"
          - "Architektur:   {{ ansible_architecture }}"
          - "CPUs:          {{ ansible_processor_vcpus }}"
          - "RAM (MB):      {{ ansible_memtotal_mb }}"
          - "Freier RAM:    {{ ansible_memory_mb.nocache.free }} MB"
          - "IP (eth0):     {{ ansible_default_ipv4.address | default('n/a') }}"
          - "Kernel:        {{ ansible_kernel }}"
          - "Python:        {{ ansible_python_version }}"

    - name: Nur Facts sammeln ohne Playbook (Ad-hoc)
      # ansible all -m setup -a "filter=ansible_memory*"
      # ansible all -m setup -a "filter=ansible_network*"
      debug:
        msg: "OS-spezifisches Paket-Tool: {{ 'apt' if ansible_os_family=='Debian' else 'yum' }}"

    - name: Niedrigen RAM erkennen
      debug:
        msg: "WARNUNG: Weniger als 512 MB RAM!"
      when: ansible_memtotal_mb < 512

    # Selektives Fact-Gathering (schneller)
    # gather_facts: true
    # gather_subset:
    #   - network
    #   - hardware
    #   - "!facter"
    #   - "!ohai"

Magic Variables & Custom Facts

Code anzeigen
# Magic Variables in Playbooks
---
- name: Magic Variables demonstrieren
  hosts: all

  tasks:
    - name: Inventory-Informationen
      debug:
        msg:
          - "Mein Name im Inventory: {{ inventory_hostname }}"
          - "Kurzname:               {{ inventory_hostname_short }}"
          - "Alle Webserver:         {{ groups['webserver'] | join(', ') }}"
          - "Bin ich ein Webserver?: {{ inventory_hostname in groups['webserver'] }}"
          - "Anzahl Hosts in all:    {{ groups['all'] | length }}"

    - name: Variablen anderer Hosts lesen
      debug:
        msg: "IP von web01: {{ hostvars['web01']['ansible_host'] | default('unbekannt') }}"
      when: inventory_hostname != 'web01'

# Custom Facts — Datei auf dem Target
# /etc/ansible/facts.d/app.fact (JSON)
# {
#   "version": "2.3.1",
#   "environment": "production",
#   "deployed_at": "2024-01-15"
# }

# Oder Shell-Script (muss gültiges JSON ausgeben):
# #!/bin/bash
# echo '{"disk_free_gb": '$(df -BG / | awk 'NR==2{print $4}' | tr -d G)'}'

# Zugriff im Playbook:
# {{ ansible_local.app.version }}
# {{ ansible_local.app.environment }}

# Custom Fact deployen und laden:
- name: Custom Fact hinterlegen
  copy:
    src: files/app.fact
    dest: /etc/ansible/facts.d/app.fact
    mode: "0644"

- name: Facts neu laden
  setup:
    filter: ansible_local

setup: filter: ansible_local lädt nur Custom Facts neu — viel schneller als alle Facts neu zu sammeln.

Aufgabe

Schreibe ein Playbook, das Facts sammelt, OS-spezifisch reagiert, Magic Variables für einen Cross-Host-Check nutzt und einen Custom Fact deployed.

Anforderungen
  1. gather_facts und ansible_os_family für OS-Zweige genutzt
  2. ansible_memtotal_mb und ansible_processor_vcpus in Logik eingebaut
  3. hostvars["anderer_host"] korrekt referenziert
  4. groups["gruppe"] für Mitgliedschaftsprüfung genutzt
  5. Custom Fact als JSON-Datei in facts.d deployed
  6. setup: filter: ansible_local zum Reload
Akzeptanzkriterien
  • Facts stehen im Playbook korrekt zur Verfügung
  • Custom Fact per ansible_local.name.key abrufbar
  • Cross-Host-Referenz liefert korrekten Wert
