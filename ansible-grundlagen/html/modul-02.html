Playbooks & Task-Module

Cheat Sheets
linux
Lernziele
  • Die YAML-Struktur eines Playbooks verstehen: plays, tasks, modules
  • Wichtige Module einsetzen: apt/yum, service, copy, template, user, file
  • Mit become Privilegien eskalieren
  • Task-Output mit register erfassen und mit debug ausgeben
Hintergrund

Ein Playbook ist eine YAML-Datei mit einer Liste von Plays. Jeder Play hat: hosts (Ziel-Gruppe), become (Privilege Escalation), vars (Variablen) und tasks (Liste von Aufgaben). Jeder Task ruft ein Modul auf. Module sind idempotent: apt: name=nginx state=present installiert nginx nur wenn es noch nicht installiert ist. Zweites Ausführen: keine Änderung, kein Fehler.

register speichert den Task-Output in eine Variable. Die Variable hat Felder: stdout, stderr, rc (Return Code), changed, failed. Mit debug: var=meine_variable kann man sie ausgeben. when: my_var.rc != 0 erlaubt Conditional auf Basis des Outputs. Das ist der Grundstein für Playbooks, die auf den Systemzustand reagieren.

Schlüsselkonzepte

Erstes Playbook: Webserver-Setup

Code anzeigen
---
# webserver.yml
- name: Webserver einrichten
  hosts: webserver
  become: true
  vars:
    nginx_port: 80
    doc_root: /var/www/html

  tasks:
    - name: nginx installieren
      apt:
        name: nginx
        state: present
        update_cache: true
      tags: install

    - name: Document Root erstellen
      file:
        path: "{{ doc_root }}"
        state: directory
        owner: www-data
        group: www-data
        mode: "0755"

    - name: Index-Seite kopieren
      copy:
        content: "
Ansible managed
"
        dest: "{{ doc_root }}/index.html"
        owner: www-data
        mode: "0644"
      notify: nginx reload

    - name: nginx starten und aktivieren
      service:
        name: nginx
        state: started
        enabled: true

    - name: nginx-Version prüfen
      command: nginx -v
      register: nginx_version
      changed_when: false   # Kommando ändert nichts

    - name: Version ausgeben
      debug:
        msg: "Installiert: {{ nginx_version.stderr }}"  # nginx -v schreibt auf stderr

  handlers:
    - name: nginx reload
      service:
        name: nginx
        state: reloaded

# Ausführen:
# ansible-playbook webserver.yml
# ansible-playbook webserver.yml --tags install
# ansible-playbook webserver.yml --check   (Dry-run)

changed_when: false sagt Ansible, dass dieser Task nie als "geändert" gilt — wichtig für register-Tasks die nur lesen.

System-User anlegen

Code anzeigen
---
- name: Ansible-Serviceuser anlegen
  hosts: all
  become: true

  vars:
    ansible_user_name: ansible
    ansible_user_groups: [sudo, adm]
    ssh_pub_key: "{{ lookup('file', '~/.ssh/ansible_key.pub') }}"

  tasks:
    - name: User anlegen
      user:
        name: "{{ ansible_user_name }}"
        groups: "{{ ansible_user_groups }}"
        shell: /bin/bash
        create_home: true
        state: present

    - name: SSH-Key hinterlegen
      authorized_key:
        user: "{{ ansible_user_name }}"
        key: "{{ ssh_pub_key }}"
        state: present

    - name: Passwortlose sudo-Regel
      copy:
        content: "{{ ansible_user_name }} ALL=(ALL) NOPASSWD:ALL\n"
        dest: "/etc/sudoers.d/{{ ansible_user_name }}"
        validate: "visudo -cf %s"
        mode: "0440"

validate: "visudo -cf %s" prüft die sudoers-Datei vor dem Schreiben — verhindert einen ausgesperrten Root.

Aufgabe

Schreibe ein Playbook, das auf einer webserver-Gruppe nginx installiert, eine index.html deployed, den Service startet und die nginx-Version per debug ausgibt. Tags für install und config.

Anforderungen
  1. Play: hosts, become, vars korrekt
  2. apt-Modul: state=present, update_cache=true
  3. file-Modul: Verzeichnis mit korrekten Permissions
  4. copy-Modul: Datei mit owner/mode
  5. service-Modul: started + enabled
  6. register + debug: nginx-Version im Output sichtbar
  7. Handler: notify → reload bei Konfigurationsänderung
Akzeptanzkriterien
  • Playbook läuft idempotent (2. Lauf: keine changed-Tasks)
  • nginx ist nach dem Playbook erreichbar
  • Handler wird nur bei Änderungen ausgelöst
