Rollen & ansible-galaxy

Cheat Sheets
linux
Lernziele
  • Die Rollen-Verzeichnisstruktur verstehen und eine Rolle erstellen
  • Rollen in Playbooks einbinden: roles: und include_role
  • Rollen-Defaults von Rollen-Vars unterscheiden
  • Community-Rollen von Ansible Galaxy installieren und nutzen
Hintergrund

Eine Ansible-Rolle ist ein strukturiertes Verzeichnis, das Aufgaben, Variablen, Templates, Handler und Dateien nach Konvention organisiert. Rollen machen Code wiederverwendbar: einmal schreiben, in vielen Playbooks nutzen. ansible-galaxy init meine_rolle erstellt das Gerüst automatisch. Rollen-Defaults (defaults/main.yml) haben die niedrigste Priorität aller Variablen — perfekt für Werte, die Nutzer leicht überschreiben sollen.

ansible-galaxy ist das Paket-Repository für Ansible-Rollen. ansible-galaxy install geerlingguy.nginx installiert eine Community-Rolle. requirements.yml definiert Abhängigkeiten: ansible-galaxy install -r requirements.yml. Offizielle Collections (ansible.builtin, community.general, ansible.posix) erweitern das Modul-Angebot. Rollen können auch in Collections gebündelt werden.

Schlüsselkonzepte

Rollen-Struktur

Code anzeigen
# ansible-galaxy init roles/webserver
roles/
└── webserver/
    ├── defaults/
    │   └── main.yml     # Niedrigste Priorität — überschreibbar
    ├── vars/
    │   └── main.yml     # Hohe Priorität — interne Konstanten
    ├── tasks/
    │   ├── main.yml     # Einstiegspunkt
    │   ├── install.yml  # Aufgeteilt per include_tasks
    │   └── config.yml
    ├── handlers/
    │   └── main.yml
    ├── templates/
    │   └── nginx.conf.j2
    ├── files/
    │   └── index.html
    ├── meta/
    │   └── main.yml     # Rollen-Metadaten & Abhängigkeiten
    └── README.md

# roles/webserver/defaults/main.yml
nginx_port: 80
nginx_user: www-data
nginx_worker_processes: auto
nginx_vhosts: []

# roles/webserver/tasks/main.yml
---
- name: Installations-Tasks einbinden
  include_tasks: install.yml

- name: Konfigurations-Tasks einbinden
  include_tasks: config.yml

# roles/webserver/meta/main.yml
galaxy_info:
  role_name: webserver
  author: dein_name
  description: Nginx Webserver-Rolle
  min_ansible_version: "2.14"
dependencies:
  - role: common   # Abhängigkeit von anderer Rolle

Rollen in Playbooks & Galaxy

Code anzeigen
# site.yml — Rollen einbinden
---
- name: Webserver konfigurieren
  hosts: webserver
  become: true
  roles:
    - role: common          # immer zuerst
    - role: webserver       # mit Default-Werten
    - role: webserver       # mit überschriebenen Werten
      vars:
        nginx_port: 8080
        nginx_worker_processes: 4

# Alternativ: dynamisch mit include_role
- name: Rolle je nach OS
  include_role:
    name: "{{ ansible_os_family | lower }}_hardening"

# requirements.yml — Externe Abhängigkeiten
---
roles:
  - name: geerlingguy.nginx
    version: "3.2.0"
  - name: geerlingguy.php
    version: "5.0.0"
  - src: https://github.com/example/myrole
    name: custom_role

collections:
  - name: community.general
    version: ">=7.0.0"
  - name: ansible.posix

# Installieren
# ansible-galaxy install -r requirements.yml
# ansible-galaxy role list
# ansible-galaxy role remove geerlingguy.nginx

requirements.yml mit versionierten Abhängigkeiten in Git committen — so ist das Playbook reproduzierbar.

Aufgabe

Erstelle eine Rolle "common" (Basis-Pakete, User, NTP) und eine Rolle "webserver" (nginx, vhosts per Variable). Binde beide in ein Playbook ein. Installiere eine Galaxy-Rolle als Vergleich.

Anforderungen
  1. ansible-galaxy init für beide Rollen verwendet
  2. defaults/main.yml: alle überschreibbaren Werte
  3. tasks aufgeteilt in install.yml und config.yml
  4. meta/main.yml: Abhängigkeit common → webserver
  5. requirements.yml mit 1+ Galaxy-Rolle und Version
  6. ansible-galaxy install -r requirements.yml korrekt
Akzeptanzkriterien
  • Rollen laufen in korrekter Abhängigkeitsreihenfolge
  • Überschriebene defaults-Werte greifen
  • Galaxy-Rolle funktioniert ohne Modifikation
