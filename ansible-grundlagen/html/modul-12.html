Abschlussprojekt: Enterprise Hardening-Rolle

Cheat Sheets
linux
Lernziele
  • Eine vollständige, getestete Hardening-Rolle nach Enterprise-Standards erstellen
  • Vault für alle Secrets, Tags für alle Tasks, Idempotenz sichergestellt
  • Compliance-Report-Playbook und Hardening-Playbook verbinden
  • CI/CD-Pipeline für automatisches Testen mit Molecule skizzieren
Hintergrund

Eine Enterprise-taugliche Ansible-Rolle erfüllt folgende Kriterien: Idempotenz (beliebig oft ausführbar ohne Seiteneffekte), Vollständige Dokumentation (README.md mit Variablen, Anforderungen, Beispielen), Vault für alle Secrets, Tags für granulare Ausführung, Tests (Molecule + Testinfra/pytest), unterstützt mehrere OS (Debian/RedHat), CI/CD-Integration (GitHub Actions, GitLab CI).

Molecule ist das Standard-Test-Framework für Ansible-Rollen. Es erstellt eine temporäre Testumgebung (Docker, Vagrant, EC2), führt die Rolle aus, prüft Idempotenz (zweite Ausführung ohne changed) und führt Testinfra-Tests aus (Test ob SSH-Config korrekt, ob Dienste laufen). molecule init role meine_rolle erstellt Gerüst. molecule test führt den kompletten Test-Zyklus aus.

Molecule-Tests & CI/CD

Code anzeigen
# molecule/default/molecule.yml
---
dependency:
  name: galaxy
driver:
  name: docker
platforms:
  - name: ubuntu2204
    image: geerlingguy/docker-ubuntu2204-ansible
    pre_build_image: true
  - name: debian12
    image: geerlingguy/docker-debian12-ansible
    pre_build_image: true
provisioner:
  name: ansible
verifier:
  name: ansible

# molecule/default/verify.yml
---
- name: Verify Hardening
  hosts: all
  gather_facts: true
  tasks:
    - name: SSH PermitRootLogin prüfen
      command: sshd -T
      register: sshd_out
      changed_when: false
      failed_when: "'permitrootlogin no' not in sshd_out.stdout"

    - name: sysctl ASLR prüfen
      command: sysctl kernel.randomize_va_space
      register: aslr
      changed_when: false
      failed_when: "'2' not in aslr.stdout"

    - name: auditd läuft
      service_facts:
      register: services

    - assert:
        that: "'auditd.service' in services.ansible_facts.services"
        fail_msg: "auditd läuft nicht"

# .github/workflows/molecule.yml
name: Molecule Test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install molecule[docker] ansible
      - run: molecule test
        working-directory: roles/server_hardening
        env:
          ANSIBLE_VAULT_PASSWORD: ${{ secrets.VAULT_PASSWORD }}

molecule test führt aus: create → prepare → converge → idempotency → verify → destroy. Idempotenz-Test ist automatisch: zweite Ausführung darf keine changed-Tasks haben.

Aufgabe

Erstelle die vollständige Hardening-Rolle inkl. README, Vault für Secrets, Tags für alle Tasks und einem Molecule-Test-Gerüst. Führe das Compliance-Check-Playbook aus Modul 10 nach der Härtung aus und vergleiche vorher/nachher.

Anforderungen
  1. Rollensstruktur: tasks aufgeteilt in 7+ Dateien
  2. defaults/main.yml: alle konfigurierbaren Parameter
  3. vars/Debian.yml und vars/RedHat.yml für OS-Unterschiede
  4. Vault: mind. 3 Secrets korrekt eingebunden
  5. Tags: jeder Task hat mind. einen Tag
  6. Idempotenz: 2. Ausführung zeigt 0 changed-Tasks
  7. Molecule: molecule.yml + converge.yml + verify.yml vorhanden
  8. Compliance-Report: PASS-Quote steigt nach Härtung
  9. README.md: Variablen, Anforderungen, Beispiele
Akzeptanzkriterien
  • Rolle läuft idempotent auf Debian und Ubuntu
  • Alle Tags funktionieren selektiv
  • Molecule verify.yml bestätigt Härtungsmaßnahmen
  • Compliance-Report zeigt signifikante PASS-Verbesserung
