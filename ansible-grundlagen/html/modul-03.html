Variablen & Jinja2-Templates

Cheat Sheets
linux
Lernziele
  • Die Variablen-Prioritätsreihenfolge in Ansible verstehen
  • host_vars und group_vars-Verzeichnisse korrekt einsetzen
  • Jinja2-Templates mit template-Modul deployen
  • Jinja2-Filter für String-Manipulation und Datenformatierung nutzen
Hintergrund

Ansible hat 22 Variablen-Prioritätsstufen. Die wichtigsten (niedrig→hoch): role defaults → group_vars/all → group_vars/gruppenname → host_vars/hostname → play vars → task vars → extra-vars (-e). Höhere Priorität gewinnt immer. group_vars/all.yml gilt für alle Hosts, group_vars/webserver.yml nur für die webserver-Gruppe, host_vars/web01.yml nur für web01.

Jinja2 ist die Template-Engine von Ansible. In YAML-Werten: {{ variable }}. In Templates (.j2-Dateien): voller Jinja2-Zugriff inkl. Loops, Conditions, Filter. Filter transformieren Werte: {{ "hallo" | upper }} → HALLO, {{ liste | join(",") }}, {{ zahl | default(0) }}, {{ pfad | basename }}, {{ json_string | from_json }}. Das template-Modul kopiert eine .j2-Datei auf den Host und ersetzt alle Variablen.

Schlüsselkonzepte

Variablen-Hierarchie & group_vars

Code anzeigen
# Verzeichnisstruktur
project/
├── ansible.cfg
├── inventory/
│   └── hosts.ini
├── group_vars/
│   ├── all.yml          # gilt für alle Hosts
│   ├── webserver.yml    # gilt für [webserver]
│   └── dbserver.yml     # gilt für [dbserver]
├── host_vars/
│   └── web01.yml        # gilt nur für web01
└── playbooks/
    └── site.yml

# group_vars/all.yml
ntp_servers:
  - 0.pool.ntp.org
  - 1.pool.ntp.org
timezone: Europe/Berlin
log_dir: /var/log/app

# group_vars/webserver.yml
nginx_worker_processes: auto
nginx_keepalive_timeout: 65
nginx_max_body_size: 10m
app_port: 8080

# host_vars/web01.yml
nginx_worker_processes: 4   # Überschreibt group_vars
primary_node: true

Jinja2-Templates

Code anzeigen
# templates/nginx.conf.j2
worker_processes {{ nginx_worker_processes }};
events {
    worker_connections 1024;
}
http {
    keepalive_timeout {{ nginx_keepalive_timeout }};
    client_max_body_size {{ nginx_max_body_size }};

    {% for vhost in nginx_vhosts %}
    server {
        listen 80;
        server_name {{ vhost.name }};
        root {{ vhost.root | default("/var/www/html") }};

        {% if vhost.ssl | default(false) %}
        listen 443 ssl;
        ssl_certificate /etc/ssl/{{ vhost.name }}.crt;
        {% endif %}

        location / {
            proxy_pass http://127.0.0.1:{{ app_port }};
        }
    }
    {% endfor %}
}

# playbook-Task
- name: nginx.conf deployen
  template:
    src: templates/nginx.conf.j2
    dest: /etc/nginx/nginx.conf
    owner: root
    group: root
    mode: "0644"
    validate: "nginx -t -c %s"
  notify: nginx reload

# Nützliche Filter:
# {{ hostname | upper }}              → WEB01
# {{ liste | length }}                → 3
# {{ var | default("fallback") }}     → fallback wenn undefined
# {{ pfad | basename }}               → datei.conf
# {{ wert | bool }}                   → True/False
# {{ dict | dict2items }}             → [{key:...,value:...}]
# {{ items | selectattr("active") }}  → filtern nach Attribut

validate: "nginx -t -c %s" prüft die generierte Config vor dem Schreiben — genau wie beim sudoers-Beispiel.

Aufgabe

Erstelle eine group_vars-Struktur für 2 Gruppen mit 5+ Variablen pro Gruppe und ein Jinja2-Template für eine Konfigurationsdatei, das mindestens eine Schleife und eine Conditional enthält.

Anforderungen
  1. group_vars/all.yml + group_vars/webserver.yml vorhanden
  2. host_vars für mindestens einen Host
  3. template-Modul mit .j2-Datei deployed
  4. J2-Template: {% for %} Schleife korrekt
  5. J2-Template: {% if %} Conditional korrekt
  6. Filter: default(), upper oder basename eingesetzt
  7. validate in template-Task gesetzt
Akzeptanzkriterien
  • Template wird mit korrekten Variablen gerendert
  • host_vars überschreiben group_vars wie erwartet
  • validate-Befehl wird ausgeführt
