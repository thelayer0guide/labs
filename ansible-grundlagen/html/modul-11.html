Dynamische Inventories & Cloud-Integration

Cheat Sheets
linux
Lernziele
  • Dynamische Inventory-Plugins für AWS EC2 und Docker konfigurieren
  • Einen eigenen Inventory-Script als Python-Script schreiben
  • Constructed-Inventory für automatisches Gruppen-Mapping nutzen
  • Hosts mit Tags/Labels automatisch in Gruppen einteilen
Hintergrund

Statische Inventories werden bei 100+ Hosts oder Cloud-Infrastruktur unhandhabbar. Dynamische Inventories fragen live die aktuelle Infrastruktur ab: AWS EC2, GCP, Azure, VMware, Docker, Kubernetes. ansible-inventory --list ruft das Plugin auf und zeigt JSON. Inventory-Plugins werden in inventory/aws_ec2.yml (oder .yaml) konfiguriert und durch den Plugin-Typ erkannt.

Constructed-Inventory-Plugin: Erzeugt Gruppen aus Facts und Variablen: keyed_groups bildet Gruppen aus Key-Value-Paaren (z.B. alle Hosts mit tag:Environment=production in die Gruppe tag_Environment_production). compose setzt neue Variablen aus bestehenden zusammen. So landen AWS-EC2-Instanzen automatisch in Gruppen basierend auf ihren Tags — kein manuelles Pflegen mehr.

Schlüsselkonzepte

AWS EC2 Dynamisches Inventory

Code anzeigen
# inventory/aws_ec2.yml
plugin: amazon.aws.aws_ec2
regions:
  - eu-central-1
  - us-east-1

# Filter: Nur laufende Instanzen
filters:
  instance-state-name: running
  "tag:Project": myapp

# Gruppen aus Tags bilden
keyed_groups:
  # Gruppe: tag_Environment_production, tag_Environment_staging
  - key: tags.Environment
    prefix: env
    separator: "_"
  # Gruppe nach Instanztyp: instance_type_t3_medium
  - key: instance_type
    prefix: instance_type

# Konstruierte Variablen und Gruppen
compose:
  ansible_host: private_ip_address   # oder public_ip_address
  ansible_user: "'ubuntu'"           # Statischer Wert
  environment: tags.Environment

groups:
  # Bedingungsbasierte Gruppe
  production: "tags.Environment == 'production'"
  webserver:  "tags.Role == 'web'"
  dbserver:   "tags.Role == 'db'"

# Voraussetzungen:
# pip install boto3 botocore
# aws configure (oder AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY als Env)

# Testen:
# ansible-inventory -i inventory/aws_ec2.yml --list
# ansible-inventory -i inventory/aws_ec2.yml --graph
# ansible -i inventory/aws_ec2.yml all -m ping

Eigenes Inventory-Script

Code anzeigen
#!/usr/bin/env python3
# inventory/dynamic_inventory.py
"""Liest Hosts aus einer CMDB-API oder Datei und gibt Ansible-JSON zurück."""
import json, sys, os

def get_inventory():
    # In der Praxis: API-Aufruf, z.B. requests.get("http://cmdb/hosts")
    # Hier: Beispieldaten
    return {
        "_meta": {
            "hostvars": {
                "web01": {"ansible_host": "10.0.1.10", "role": "frontend"},
                "web02": {"ansible_host": "10.0.1.11", "role": "frontend"},
                "db01":  {"ansible_host": "10.0.2.10", "role": "database"},
            }
        },
        "webserver": {
            "hosts": ["web01", "web02"],
            "vars": {"nginx_port": 80}
        },
        "dbserver": {
            "hosts": ["db01"],
            "vars": {"db_port": 5432}
        },
        "all": {
            "children": ["webserver", "dbserver"]
        }
    }

if __name__ == "__main__":
    if "--list" in sys.argv:
        print(json.dumps(get_inventory(), indent=2))
    elif "--host" in sys.argv:
        host = sys.argv[sys.argv.index("--host") + 1]
        inv  = get_inventory()
        vars = inv.get("_meta", {}).get("hostvars", {}).get(host, {})
        print(json.dumps(vars, indent=2))

# chmod +x inventory/dynamic_inventory.py
# ansible-inventory -i inventory/dynamic_inventory.py --list
# ansible -i inventory/dynamic_inventory.py all -m ping

_meta.hostvars erlaubt Ansible, alle Host-Variablen in einem Aufruf abzurufen — effizienter als --host für jeden Host einzeln.

Aufgabe

Konfiguriere ein dynamisches Inventory (AWS EC2 oder Docker) mit keyed_groups und compose. Schreibe alternativ ein eigenes Python-Inventory-Script das Hosts aus einer JSON-Datei liest.

Anforderungen
  1. Inventory-Plugin (aws_ec2.yml oder docker_containers.yml)
  2. keyed_groups: mind. 2 Gruppen aus Attributen
  3. compose: ansible_host korrekt gesetzt
  4. groups: bedingungsbasierte Gruppe
  5. ansible-inventory --graph zeigt dynamische Gruppen
  6. Eigenes Script: --list und --host implementiert
Akzeptanzkriterien
  • ansible-inventory --list gibt valides JSON zurück
  • Hosts landen in korrekten Gruppen
  • ansible -m ping funktioniert gegen dynamische Hosts
