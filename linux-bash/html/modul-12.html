Bash Profi-Patterns

Cheat Sheets
bash
Lernziele
  • Lockfile-Pattern für exklusive Skript-Ausführung
  • IPC zwischen Bash-Prozessen (Named Pipes, Sockets)
  • Parallele Verarbeitung mit Job-Control und GNU Parallel
  • Unit-Tests für Bash-Skripte mit bats-core
  • Profiling und Debugging (set -x, bash -n)
Hintergrund

Professionelle Bash-Skripte sind idempotent, robust und testbar. Das bedeutet: sie erkennen wenn sie schon laufen (Lockfile), räumen nach sich auf (trap), sind parallelisierbar und haben automatisierte Tests.

bats-core (Bash Automated Testing System) bringt Unit-Test-Konzepte in die Bash-Welt: @test-Annotationen, Assertions (assert_output, assert_success) und TAP-Ausgabe für CI-Integration.

Schlüsselkonzepte

Lockfile & Debugging

Code anzeigen
#!/bin/bash
set -euo pipefail

# Lockfile-Pattern
LOCKFILE="/var/run/myscript.lock"
if ! mkdir "$LOCKFILE" 2>/dev/null; then
    echo "Skript läuft bereits (Lock: $LOCKFILE)" >&2
    exit 1
fi
trap "rmdir $LOCKFILE" EXIT

# Debugging
set -x   # jeden Befehl ausgeben
bash -n script.sh  # Syntax-Check ohne Ausführung
bash -x script.sh  # Execution-Trace

# Performance
time ./script.sh

# Profiling (episch): PS4 setzen
PS4='+ ${BASH_SOURCE}:${LINENO}:${FUNCNAME[0]}: '
set -x

GNU Parallel & bats

Code anzeigen
# GNU Parallel: 4 Worker, eine URL pro Job
cat urls.txt | parallel -j4 curl -s {} -o /dev/null

# Named Pipe für IPC
mkfifo /tmp/mypipe
producer() { for i in {1..5}; do echo "$i"; done; } > /tmp/mypipe &
consumer() { while read line; do echo "Got: $line"; done; } < /tmp/mypipe
wait

# bats-Testdatei
#!/usr/bin/env bats
@test "disk-report gibt Top-10 aus" {
    run ./disk-report.sh
    assert_success
    assert_output --partial "G"
}

@test "leere Eingabe gibt Exit 0" {
    run ./disk-report.sh /nonexistent
    assert_failure
}
Aufgabe

Erweitere syscheck.sh aus Modul 7: füge Lockfile-Schutz hinzu, parallelisiere alle Checks mit &+wait, schreibe 3 bats-Tests und füge Execution-Tracing per Flag -d hinzu.

Anforderungen
  1. Lockfile verhindert gleichzeitige Ausführung
  2. Alle Checks laufen parallel
  3. Mindestens 3 bats-Tests vorhanden
  4. Flag -d aktiviert set -x
Akzeptanzkriterien
  • bats: alle Tests grün
  • Lockfile wird bei vorzeitigem Exit gelöscht (trap)
  • Parallele Version ist messbar schneller als sequentielle
