Hintergrund

Properties, Decorators und Generatoren sind die Werkzeuge, die Python-Code von 'funktioniert' zu 'idiomatisch' machen. Ein Property macht aus einer Methode ein Attribut — ohne die API zu aendern. Ein Decorator macht Querschnittslogik (Logging, Caching, Timing) zu einer wiederverwendbaren Funktion. Ein Generator berechnet Werte lazy — entscheidend bei grossen Datenmengen.

Context Manager (__enter__ / __exit__) sind das Muster hinter with open(...) — jetzt schreibst du eigene. functools.lru_cache ist die einfachste Form von Memoization.

Monatsprojekt Plugin-System mit Decorator-Registry

Baue ein erweiterbares Plugin-System: ein @register-Decorator traegt Funktionen in eine globale Registry ein. Ein Generator liefert Plugins lazy. Eine Abstract Base Class definiert die Plugin-Schnittstelle.

  • @register(name, version)-Decorator — traegt dekorierte Funktion in REGISTRY ein
  • class Plugin(ABC) mit abstractmethod run(data: dict) -> dict
  • def load_plugins(path) als Generator — laedt lazy aus Verzeichnis
  • class Timer als Context Manager: misst Ausfuehrungszeit, gibt ms aus
  • Mindestens 3 Demo-Plugins registriert und ueber Registry aufgerufen
  • functools.lru_cache fuer eine teure Berechnung (z. B. Fibonacci)
Akzeptanzkriterien
@register('uppercase', '1.0')
def uppercase_plugin(data):
    return {k: v.upper() if isinstance(v, str) else v for k, v in data.items()}

for name, fn in REGISTRY.items():
    print(name, fn({'msg': 'hallo'}))

with Timer() as t:
    fib(35)
print(f'Dauer: {t.elapsed_ms:.1f} ms')
