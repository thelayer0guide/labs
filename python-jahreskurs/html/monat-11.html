W 41
pytest in der Tiefe
  • @pytest.fixture: Setup/Teardown elegant
  • tmp_path: Dateisystem-Tests ohne echte Dateien
  • @pytest.mark.parametrize: viele Inputs, eine Testfunktion
  • unittest.mock.patch: Netzwerk/Dateisystem mocken
  • pytest-cov: Coverage-Report
  • TDD-Flow: Test schreiben → scheitern → implementieren → grün
import pytest from unittest.mock import patch, MagicMock @pytest.mark.parametrize("algo,expected_len", [ ("md5", 32), ("sha1", 40), ("sha256", 64) ]) def test_hash_laenge(tmp_path, algo, expected_len): f = tmp_path / "test.bin" f.write_bytes(b"Testdaten") ergebnis = hash_file(f, [algo]) assert len(ergebnis[algo]) == expected_len

W 43
Packaging & Verteilung
  • pyproject.toml: [project], [build-system], [project.scripts]
  • hatchling oder setuptools als Build-Backend
  • pip install -e .: editable install für Entwicklung
  • pipx install .: isoliertes globales Tool
  • Wheel (.whl) bauen: python -m build
  • PyPI-Upload (optional): twine upload dist/*
# pyproject.toml [project] name = "uctl" version = "0.1.0" requires-python = ">=3.11" dependencies = ["typer", "rich", "httpx"] [project.scripts] uctl = "uctl.cli:app" # pipx install . → uctl [project.entry-points."uctl.plugins"] hash = "uctl.tools.hash:HashTool"

Architektur & Design Patterns
  • Logging: logging.getLogger(), Handler, Formatter, Levels
  • Strategy Pattern: austauschbare Algorithmen
  • Factory Pattern: Objekte zur Laufzeit erstellen
  • Observer Pattern: Events ohne enge Kopplung
  • Plugin-Architektur: importlib.metadata.entry_points
  • Konfigurationsmanagement: zentrale Config-Klasse
import logging from importlib.metadata import entry_points log = logging.getLogger("uctl") def lade_plugins() -> dict: plugins = {} for ep in entry_points(group="uctl.plugins"): plugins[ep.name] = ep.load() log.debug(f"Plugin geladen: {ep.name}") return plugins
