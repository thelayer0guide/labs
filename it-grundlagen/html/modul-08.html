Prozesse & Threads

Cheat Sheets
linux
Lernziele
  • Den Unterschied zwischen Prozess und Thread erklären
  • Prozess-Zustände und den Scheduler verstehen
  • Fork, Exec und Copy-on-Write kennen
  • Prozess-Interaktion (Signale, IPC) und Deadlocks erläutern
Hintergrund

Ein Prozess ist eine laufende Instanz eines Programms mit eigenem Adressraum, Datei-Deskriptoren und Ressourcen. Threads sind leichtgewichtige Ausführungseinheiten innerhalb eines Prozesses — sie teilen sich den Adressraum, haben aber eigene Register und Stack. Der OS-Scheduler entscheidet, welcher Prozess wann die CPU bekommt (Round-Robin, Priority-basiert, CFS in Linux).

fork() erstellt eine exakte Kopie des aktuellen Prozesses (Copy-on-Write für Effizienz). exec() ersetzt das Prozess-Image mit einem neuen Programm. Diese fork-exec-Kombination ist der Standard-Mechanismus zum Starten von Prozessen in Unix. Signale (SIGKILL, SIGTERM, SIGINT) sind der primäre Kommunikationsweg zwischen Prozessen. Race Conditions und Deadlocks entstehen, wenn mehrere Threads/Prozesse um dieselben Ressourcen konkurrieren.

Schlüsselkonzepte

Prozess-Management Linux

Code anzeigen
# Prozessliste
ps aux
ps aux --sort=-%cpu | head -10

# Prozess-Baum (PID-Hierarchie)
pstree -p

# Threads eines Prozesses
ps -eLf | grep firefox
ls /proc/$$/task/

# Prozess-Signale
kill -l              # alle Signale
kill -TERM      # graceful
kill -KILL      # sofort
killall -HUP nginx

# Priorität
nice -n 10 command
renice -n 5 -p

Prozess-Details & IPC

Code anzeigen
# Prozess-Details im /proc
cat /proc/$$/status
cat /proc/$$/maps
cat /proc/$$/fd -la 2>/dev/null

# Inter-Process Communication
ipcs        # Shared Memory, Semaphore, Message Queues
ipcs -m     # nur Shared Memory

# Deadlock-Demo
# Prozess A: lock(mutex1); lock(mutex2)
# Prozess B: lock(mutex2); lock(mutex1)
# -> Deadlock!

# Offene Dateien eines Prozesses
lsof -p $$

/proc/$$ ist ein virtuelles Dateisystem — jede Zahl ist eine PID. Malware nutzt /proc zum Lesen von Prozess-Speicher anderer Prozesse (PTRACE_ATTACH).

Aufgabe

Starte mehrere Prozesse, analysiere deren /proc-Einträge und sende verschiedene Signale. Erkläre den fork-exec-Mechanismus und erstelle ein einfaches Python-Skript, das Kindprozesse erzeugt.

Anforderungen
  1. Unterschied Prozess vs. Thread klar formulieren
  2. ps aux und pstree ausgeben und interpretieren
  3. /proc/[PID]/status für einen laufenden Prozess analysieren
  4. SIGTERM vs. SIGKILL: Unterschied erklären
  5. Python-Script mit os.fork() oder subprocess.Popen() schreiben
Akzeptanzkriterien
  • Prozess-/Thread-Unterschied korrekt erklärt
  • /proc-Analyse durchgeführt
  • Fork/Exec-Mechanismus verstanden
