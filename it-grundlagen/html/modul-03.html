CPU-Architektur & Befehlssatz

Hintergrund

Die CPU (Central Processing Unit) ist das Herz jedes Computers. Sie besteht aus der ALU (Arithmetic Logic Unit) für Berechnungen, Registern für ultraschnellen temporären Speicher und der Control Unit, die den Programmfluss steuert. Der grundlegende Arbeitszyklus lautet: Fetch (Befehl aus RAM holen), Decode (Befehl entschlüsseln), Execute (Befehl ausführen).

Für Security-Experten sind CPU-Register essentiell: EIP/RIP (Instruction Pointer) zeigt auf den nächsten Befehl — ihn zu kontrollieren bedeutet Code-Ausführung. ESP/RSP (Stack Pointer) zeigt auf den Stack-Kopf. EBP/RBP ist der Frame Pointer. Das Verständnis dieser Register ist Grundvoraussetzung für Buffer Overflows und ROP-Chains.

Schlüsselkonzepte

Register in x86/x86-64

Code anzeigen
# 64-bit Register (x86-64)
# RAX, RBX, RCX, RDX  - General Purpose
# RSI, RDI            - Source/Destination Index
# RSP                 - Stack Pointer
# RBP                 - Base Pointer
# RIP                 - Instruction Pointer

# Teilregister von RAX:
# RAX (64-bit) -> EAX (32-bit) -> AX (16-bit) -> AH/AL (8-bit)

# Register in GDB anzeigen
# gdb ./programm
# (gdb) info registers
# (gdb) x/10i $rip

CPU-Infos unter Linux

Code anzeigen
# CPU-Details anzeigen
cat /proc/cpuinfo | head -30
lscpu

# Architektur ermitteln
uname -m     # x86_64 oder aarch64
arch

# Befehlssatz-Extensions prüfen
grep flags /proc/cpuinfo | head -1
# Wichtige Flags: sse4_2, avx, aes (AES-NI)

# Kerne und Threads
lscpu | grep -E "CPU|Thread|Core|Socket"

AES-NI (aes flag in /proc/cpuinfo) bedeutet Hardware-beschleunigtes AES — relevant für Disk-Encryption-Performance.
