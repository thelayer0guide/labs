OS-Forensik & Artefakte

Cheat Sheets
linux bash
Lernziele
  • Forensische Artefakte unter Linux und Windows kennen
  • Bash-History, /proc und /var/log als Forensik-Quellen nutzen
  • Windows-Artefakte (Prefetch, Shellbags, Recent Files) analysieren
  • Timeline-Forensik: Zeitstempel-Manipulationen erkennen
Hintergrund

OS-Forensik analysiert Systemzustände und Ereignisse nach einem Sicherheitsvorfall. Das Ziel: Was wurde wann von wem getan? Artefakte sind Spuren, die Aktivität belegen. Unter Linux: ~/.bash_history (Befehle), /var/log/auth.log (Logins), /proc/[PID]/ (laufende Prozesse), /tmp/ (temporäre Dateien), Crontabs, SUID-Dateien.

Windows bietet reichhaltige forensische Artefakte: Prefetch-Dateien (wann welche Anwendung gestartet), Registry-Shellbags (Verzeichnisnavigation), Recent Files (MRU-Listen), LNK-Files (Verknüpfungen zu zuletzt geöffneten Dateien), Windows Event Logs, Browser-History. Timestomping (Zeitstempel-Manipulation) kann $STANDARD_INFORMATION-Zeiten ändern, aber $FILE_NAME-Zeiten im NTFS-MFT bleiben meist unverändert.

Schlüsselkonzepte

Linux-Forensik Artefakte

Code anzeigen
# Bash-History aller Benutzer
cat /root/.bash_history
cat /home/*/.bash_history 2>/dev/null

# Zuletzt erstellte/geänderte Dateien
find / -mtime -1 -type f 2>/dev/null | head -20  # letzte 24h
find /tmp /var/tmp -type f -newer /tmp 2>/dev/null

# Netzwerk-Verbindungen bei Einbruch
ss -antp
netstat -antp

# Versteckte Dateien
find / -name ".*" -type f 2>/dev/null | grep -v ".cache"

# SUID-Dateien (Veränderungen?)
find / -perm -4000 -type f 2>/dev/null > suid_now.txt
diff suid_before.txt suid_now.txt

Timeline & Zeitstempel

Code anzeigen
# Inode-Zeiten analysieren
stat /etc/passwd
# Access: (atime)
# Modify: (mtime) - Inhalt geändert
# Change: (ctime) - Metadaten oder Inhalt geändert

# Zeitstempel-Manipulationen (Timestomping)
touch -d "2020-01-01 00:00:00" datei.txt  # mtime ändern
ls -la datei.txt
stat datei.txt  # ctime bleibt aktuell!

# Alle Dateien nach ctime sortieren (zeigt echte Änderungen)
find /etc -type f -printf "%C+ %p\n" 2>/dev/null | sort -r | head -20

# Deleted Files (noch im RAM)
ls -la /proc/*/fd 2>/dev/null | grep deleted

ctime (Change Time) lässt sich unter Linux nicht manuell zurücksetzen — selbst nach Timestomping zeigt ctime den echten Änderungszeitpunkt.

Aufgabe

Führe eine forensische Analyse eines Linux-Systems durch: bash_history, zuletzt geänderte Dateien, aktive Netzwerkverbindungen und versteckte Dateien.

Anforderungen
  1. bash_history aller Benutzer auslesen
  2. Dateien der letzten 24h mit find -mtime -1 suchen
  3. Unterschied atime/mtime/ctime für Forensik erklären
  4. Aktive Netzwerkverbindungen mit ss -antp auflisten
  5. Timestomping: Technik und Erkennungsmethode beschreiben
Akzeptanzkriterien
  • Forensische Analyse erfolgreich durchgeführt
  • Zeitstempel-Konzepte korrekt erklärt
  • Timestomping-Nachweis via ctime demonstriert
