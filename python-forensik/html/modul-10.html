ForensicKit

Tool-Output: forensickit.py — vollautomatischer Forensik-Bericht als HTML-Report
Voraussetzungen: alle Module 01–09, importlib, subprocess, Jinja2-ähnliches Template-Building
Cheat Sheets
python json bash
Lernziele
  • Eigene Skripte als Python-Module importieren und deren Funktionen direkt aufrufen
  • Plugin-artiges Modul-System: Scanner-Module werden dynamisch geladen und ausgeführt
  • Parallel-Ausführung mehrerer Scanner mit concurrent.futures.ThreadPoolExecutor
  • Ergebnisse verschiedener Tools in eine einheitliche Datenstruktur aggregieren
  • Standalone-HTML-Report mit eingebettetem CSS und JavaScript generieren
  • Fortschrittsanzeige für lang laufende Operationen ohne externe Bibliotheken
Hintergrund

Ein Informatiker, der einen Vorfall untersucht, will nicht 9 verschiedene Tools nacheinander manuell aufrufen, Ergebnisse zusammenkopieren und dann noch einen Bericht schreiben. ForensicKit übernimmt genau das: ein einziger Befehl startet alle Scanner, sammelt die Ergebnisse und gibt einen druckbaren HTML-Report aus.

Das ist das Capstone-Modul des Kurses, weil es alle Konzepte der vorherigen Module zusammenführt: Modulimport, Parallel-Ausführung, Aggregation, HTML-Generierung. Gleichzeitig wird ein wichtiges Software-Design-Prinzip geübt: die Scanner sollen nicht direkt miteinander gekoppelt sein. ForensicKit ruft jedes Modul über eine definierte Schnittstelle auf — das ist Plugin-Architektur im Kleinen.

Der fertige Report ist ein eigenständiges HTML-Dokument ohne externe Abhängigkeiten. Er kann per E-Mail verschickt, archiviert oder in ein Ticket-System hochgeladen werden — und in 10 Jahren noch im Browser geöffnet werden.

Parallele Scanner-Ausführung

from concurrent.futures import ThreadPoolExecutor, as_completed

def run_all_scanners(target: str, config: dict,
                     scanners: list) -> list[dict]:
    results = []
    with ThreadPoolExecutor(max_workers=4) as pool:
        futures = {
            pool.submit(scanner.run_scan, target, config): scanner
            for scanner in scanners
        }
        for future in as_completed(futures):
            try:
                results.append(future.result())
            except Exception as e:
                results.append({
                    'module': futures[future].__name__,
                    'status': 'error',
                    'findings': [],
                    'summary': str(e),
                })
    return results

Aufgabe — forensickit.py
# Vollständiger Forensik-Scan
forensickit.py --target /var/www --logs /var/log --out report/

# Nur bestimmte Scanner aktivieren
forensickit.py --target /srv --scanners logs integrity secrets

# Mit Vorkonfiguration aus TOML
forensickit.py --target /var/www --config forensickit.toml

# Report ohne Ausführung aus vorhandenen JSON-Ergebnissen
forensickit.py --from-json results/*.json --out report.html

Der Output-Report forensickit_YYYYMMDD_HHMMSS.html enthält:

  • Executive Summary: Anzahl Scanner, Gesamtbefunde, kritische Funde
  • Pro Scanner: Status-Badge, Zusammenfassung, Befund-Tabelle
  • Appendix: Raw-JSON-Daten als aufklappbare Sektion
  • Generierungszeitpunkt, Ziel-Pfad, ForensicKit-Version

Das Template des HTML-Reports soll direkt als Python-String in forensickit.py eingebettet sein — kein externes Template-File. Das macht das Tool self-contained: eine einzige .py-Datei reicht.

Anforderungen
  • Mindestens 5 Scanner aus den Modulen 01–09 sind integriert
  • Scanner laufen parallel (ThreadPoolExecutor), nicht sequenziell
  • Ein fehlschlagender Scanner bricht nicht die anderen ab
  • HTML-Report ist standalone (kein externer CSS/JS)
  • Report enthält Executive Summary mit Gesamtstatus
  • --from-json erzeugt Report aus bestehenden JSON-Ergebnissen ohne erneuten Scan
  • Nur stdlib (außer für Scanner-Module selbst)
Akzeptanzkriterien
  1. Vollständiger Scan von /var/www + /var/log läuft in unter 60 Sekunden durch
  2. HTML-Report öffnet sich im Browser ohne JavaScript-Fehler
  3. Executive Summary zeigt korrekte Gesamtanzahl der Befunde
  4. Ein Scanner der abstürzt erscheint im Report als "Error" — alle anderen Scanner wurden trotzdem ausgeführt
  5. Der Report kann als eigenständige Datei ohne Internet-Verbindung vollständig dargestellt werden
