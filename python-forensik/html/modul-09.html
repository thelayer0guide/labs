Voraussetzungen: pathlib, hashlib, json, shutil.disk_usage, argparse

Lernziele
  • Verzeichnisgrößen rekursiv mit pathlib berechnen ohne du-Aufruf
  • Top-N nach Dateigröße mit heapq.nlargest() effizient bestimmen
  • Dateien per SHA256-Hash auf Duplikate prüfen (Hash-Bucketing)
  • Zwei Verzeichnisscans (Snapshots) auf Veränderungen vergleichen
  • shutil.disk_usage() für Gesamtbelegung pro Partition einsetzen
  • Formatierte Größenangaben (B, KB, MB, GB) ohne externe Bibliotheken ausgeben
Hintergrund

Speicher läuft voll, der Disk läuft voll — typisches Produktionsproblem. Die Standardlösung ist du -sh /* | sort -rh | head -20. DiskForensics macht dasselbe, gibt aber zusätzlich: Wo sind Duplikate die Platz verschwenden? Was hat sich seit dem letzten Scan verändert? Welche Verzeichnisse wachsen am schnellsten?

Duplikat-Erkennung per Hash ist dabei der elegante Ansatz: Statt Dateinamen zu vergleichen (unzuverlässig) wird der Inhalt verglichen. Zwei Dateien mit gleichem SHA256-Hash sind mit überwältigender Wahrscheinlichkeit identisch.

Der Snapshot-Diff-Mechanismus ist direkt von Modul 2 (HashGuard) verwandt — aber hier geht es um Speichereffizenz, nicht Integrität. Welche Verzeichnisse sind in der letzten Woche um mehr als 10% gewachsen?

Schlüsselkonzepte

Top-N größte Dateien

Code anzeigen
import heapq
from pathlib import Path

def top_files(root: Path, n: int = 20) -> list[tuple[int, Path]]:
    files = (
        (p.stat().st_size, p)
        for p in root.rglob('*')
        if p.is_file()
    )
    return heapq.nlargest(n, files, key=lambda x: x[0])

from collections import defaultdict

def find_duplicates(root: Path) -> dict[str, list[Path]]:
    buckets: dict[str, list[Path]] = defaultdict(list)
    for p in root.rglob('*'):
        if not p.is_file() or p.stat().st_size == 0:
            continue
        try:
            h = sha256_file(p)   # aus Modul 02
            buckets[h].append(p)
        except (PermissionError, OSError):
            pass
    return {h: paths for h, paths in buckets.items() if len(paths) > 1}

Lesbare Größenformatierung

Code anzeigen
def human_size(n_bytes: int) -> str:
    for unit in ('B', 'KB', 'MB', 'GB', 'TB'):
        if n_bytes < 1024:
            return f'{n_bytes:.1f} {unit}'
        n_bytes /= 1024
    return f'{n_bytes:.1f} PB'
Aufgabe — diskforensics.py
Code anzeigen
# Top-20 größte Dateien
diskforensics.py /data --top 20

# Verzeichnisgrößen (wie du -sh */)
diskforensics.py /data --dirs

# Duplikate finden
diskforensics.py /data --dupes

# Scan speichern
diskforensics.py scan /data --out snap1.json

# Snapshots vergleichen
diskforensics.py diff snap1.json snap2.json

# Alles kombiniert als JSON-Report
diskforensics.py /data --top 20 --dupes --format json --out disk_report.json

Duplikat-Scan auf großen Filesystems ist IO-intensiv. Für einen ersten schnellen Pass: erst Dateien nach Größe gruppieren — gleiche Größe ist Voraussetzung für Duplikat. Nur Dateien in einer Größengruppe müssen gehasht werden.

Anforderungen
  • Top-N größte Dateien werden ohne vollständiges Laden aller Pfade in RAM ermittelt
  • Verzeichnisgrößen werden rekursiv und korrekt berechnet
  • Duplikat-Erkennung nutzt Größen-Vorfilterung vor dem Hashing
  • Snapshot-Diff zeigt neue, gelöschte und in Größe veränderte Dateien
  • Alle Größenangaben werden menschenlesbar ausgegeben (KB/MB/GB)
  • Gesparte Größe durch Duplikat-Bereinigung wird in der Zusammenfassung angezeigt
  • Nur stdlib
Akzeptanzkriterien
  1. Top-20 einer Partition mit 500.000 Dateien liefert Ergebnisse in unter 30 Sekunden
  2. Duplikate werden korrekt erkannt — Test mit identischen Dateien unter verschiedenen Namen
  3. Disk-Usage-Zusammenfassung stimmt mit df -h überein (±5%)
  4. JSON-Export ist valide und kann von ForensicKit (Modul 10) eingelesen werden
  5. Berechtigungsfehler in Systemverzeichnissen führen nicht zum Abbruch
