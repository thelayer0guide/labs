SecretScanner

Tool-Output: secretscanner.py — Credentials & API-Keys in Codebasis aufspüren
Voraussetzungen: re, pathlib, json, argparse, TOML-Grundverständnis
Cheat Sheets
python regex
Lernziele
  • Regex-Pattern für verschiedene Secret-Typen entwickeln und testen
  • Binärdateien von Textdateien unterscheiden und binäre Dateien überspringen
  • Kontext-Snippets um Fundstellen herum extrahieren (N Zeilen vor/nach)
  • Gefundene Werte redaktieren (teilweise maskieren) bevor sie ausgegeben werden
  • Pattern-Konfiguration aus TOML/JSON laden statt hard-coden
  • False-Positive-Unterdrückung mit Allow-List-Dateien (.secretignore)
Hintergrund

Hardcoded Credentials in Quellcode sind eine der häufigsten Ursachen für Sicherheitsvorfälle. Datenbankpasswörter in config.py, AWS-Keys in .env-Dateien, API-Tokens direkt im Code — diese landen regelmäßig in Git-Repositories und damit potenziell öffentlich auf GitHub.

Tools wie truffleHog oder gitleaks lösen dieses Problem professionell. SecretScanner ist bewusst einfacher gehalten — aber das macht ihn lehrreicher: du siehst genau welche Regeln angewendet werden und kannst sie für dein konkretes Umfeld anpassen.

Wichtig: Das Tool soll Hinweise geben, nicht urteilen. Jeder Fund muss manuell geprüft werden. Deshalb gibt SecretScanner immer Datei, Zeile und redaktierten Kontext aus — nie den vollständigen Secret-Wert.

Schlüsselkonzepte

Secret-Pattern-Definitionen

Code anzeigen
import re

PATTERNS = {
    'private_key': re.compile(
        r'-----BEGIN (?:RSA |EC |OPENSSH )?PRIVATE KEY-----'
    ),
    'aws_key': re.compile(
        r'(?:AKIA|ASIA|AROA)[A-Z0-9]{16}'
    ),
    'generic_password': re.compile(
        r'(?:password|passwd|pwd|secret)\s*[=:]\s*["\']([^"\']{8,})["\']',
        re.IGNORECASE
    ),
    'generic_token': re.compile(
        r'(?:token|api_key|apikey|auth)\s*[=:]\s*["\']([A-Za-z0-9_\-]{16,})["\']',
        re.IGNORECASE
    ),
    'connection_string': re.compile(
        r'(?:mysql|postgres|mongodb|redis)://[^@\s]+:[^@\s]+@'
    ),
}

Binärdateien erkennen

Code anzeigen
def is_binary(path, sample_size=8192) -> bool:
    try:
        with open(path, 'rb') as f:
            chunk = f.read(sample_size)
        return b'\x00' in chunk  # Null-Bytes = binary
    except (PermissionError, OSError):
        return True

Wert redaktieren

Code anzeigen
def redact(value: str, visible: int = 4) -> str:
    if len(value) <= visible * 2:
        return '*' * len(value)
    return value[:visible] + '*' * (len(value) - visible * 2) + value[-visible:]

# "mysupersecretpassword123" → "mysu****************d123"
Aufgabe — secretscanner.py
Code anzeigen
# Ganzes Projektverzeichnis scannen
secretscanner.py /home/user/myproject

# Nur bestimmte Dateitypen
secretscanner.py /repo --include .py .yml .env .json

# .git ausschließen, Binaries überspringen (Standard)
secretscanner.py /repo --exclude .git __pycache__ node_modules

# JSON-Report für ForensicKit
secretscanner.py /repo --format json --out secrets_report.json

# Mit eigener Pattern-Datei
secretscanner.py /repo --patterns custom_rules.toml

Ausgabe je Fund: PATTERN | FILE:LINE | REDACTED_SNIPPET

Das Tool darf niemals den vollständigen Secret-Wert ausgeben — immer nur den redaktierten Wert. Wenn der Nutzer den vollständigen Wert sehen will, muss er die Datei selbst öffnen.

Anforderungen
  • Mindestens 5 Pattern-Typen sind eingebaut (private key, aws key, password=, token=, connection string)
  • Binärdateien werden automatisch übersprungen
  • Gefundene Werte werden redaktiert ausgegeben
  • Dateiname und Zeilennummer sind immer Teil der Ausgabe
  • --exclude nimmt Verzeichnisnamen und Dateiendungen entgegen
  • .secretignore-Datei im gescannten Verzeichnis wird respektiert (gitignore-ähnliche Syntax)
  • Nur stdlib
Akzeptanzkriterien
  1. Eine Test-Datei mit bekannten Dummy-Credentials wird zuverlässig gefunden
  2. Der vollständige Secret-Wert erscheint niemals in der Ausgabe
  3. Falsch-positive aus Test-Fixtures können per .secretignore unterdrückt werden
  4. Scan von 10.000 Quelldateien läuft in unter 10 Sekunden
  5. JSON-Output enthält Datei, Zeile, Pattern-Name und redaktierten Snippet
