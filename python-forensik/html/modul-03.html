ProcWatch

Tool-Output: procwatch.py — Prozess-Snapshot & Diff für Incident Response
Voraussetzungen: /proc-Filesystem, subprocess, json, dataclasses
Cheat Sheets
python bash
Lernziele
  • Das Linux-/proc-Filesystem direkt aus Python auslesen ohne externe Binaries
  • Prozessinformationen aus /proc/[PID]/status, /proc/[PID]/cmdline und /proc/[PID]/net/tcp extrahieren
  • dataclasses für strukturierte Prozess-Records mit JSON-Serialisierung nutzen
  • Zwei Prozess-Snapshots per PID, Prozessname und Commandline differenzieren
  • Berechtigungsfehler beim Auslesen privilegierter Prozesse sauber behandeln
  • Tabellarische Ausgabe mit Highlighting für neue/veränderte Prozesse
Hintergrund

Bei einem Sicherheitsvorfall stellt sich oft die Frage: Was läuft gerade auf dem System, was davon ist neu, und welche Prozesse haben sich seit dem letzten bekannt-guten Zustand verändert? ps aux zeigt den Momentanzustand — ProcWatch zeigt die Differenz zwischen zwei Momenten.

Das /proc-Filesystem ist ein virtuelles Dateisystem des Linux-Kernels. Für jeden laufenden Prozess existiert ein Verzeichnis /proc/[PID]/ mit Hunderten von Pseudo-Dateien, die den Prozesszustand beschreiben. Diese Daten sind der direkteste Weg zur Prozessforensik ohne root-Rechte.

Praktischer Einsatz: Snapshot vor einer Deployment, Snapshot danach, Diff zeigt genau welche neuen Prozesse gestartet wurden — ideal für Infrastructure-as-Code-Verifizierung und Post-Incident-Analysis.

Schlüsselkonzepte

Prozesse aus /proc lesen

Code anzeigen
from pathlib import Path
from dataclasses import dataclass, asdict
import json

@dataclass
class ProcEntry:
    pid:  int
    ppid: int
    user: str
    name: str
    cmd:  str
    vm_rss_kb: int   # Resident Set Size

def read_proc(pid: int) -> ProcEntry | None:
    try:
        status = (Path('/proc') / str(pid) / 'status').read_text()
        cmdline = (Path('/proc') / str(pid) / 'cmdline').read_bytes()
        fields = {k: v.strip() for line in status.splitlines()
                  if ':' in line for k, v in [line.split(':', 1)]}
        return ProcEntry(
            pid=pid,
            ppid=int(fields.get('PPid', 0)),
            user=fields.get('Uid', '?').split()[0],
            name=fields.get('Name', '?'),
            cmd=' '.join(cmdline.split(b'\x00')).decode(errors='replace'),
            vm_rss_kb=int(fields.get('VmRSS', '0 kB').split()[0]),
        )
    except (PermissionError, FileNotFoundError, ValueError):
        return None

Alle PIDs iterieren

Code anzeigen
def snapshot() -> dict[int, ProcEntry]:
    procs = {}
    for p in Path('/proc').iterdir():
        if p.name.isdigit():
            entry = read_proc(int(p.name))
            if entry:
                procs[entry.pid] = entry
    return procs

Diff berechnen

Code anzeigen
def diff_snapshots(old: dict, new: dict) -> dict:
    old_pids, new_pids = set(old), set(new)
    return {
        'new':     [asdict(new[p]) for p in sorted(new_pids - old_pids)],
        'gone':    [asdict(old[p]) for p in sorted(old_pids - new_pids)],
        'changed': [
            {'old': asdict(old[p]), 'new': asdict(new[p])}
            for p in old_pids & new_pids
            if old[p].name != new[p].name or old[p].cmd != new[p].cmd
        ],
    }
Aufgabe — procwatch.py
Code anzeigen
# Aktuellen Prozesszustand speichern
procwatch.py snapshot --out snap_before.json

# (etwas passiert auf dem System...)

# Differenz zum gespeicherten Snapshot anzeigen
procwatch.py diff snap_before.json snap_after.json
# → NEW     [1337] python3 /tmp/evil.py
# → GONE    [2048] mysql --host=db
# → CHANGED [999]  sshd (cmd geändert)

# Live-Tabelle aller Prozesse
procwatch.py list --sort mem --top 20

# JSON-Output für Weiterverarbeitung
procwatch.py diff snap_before.json snap_after.json --format json

Tipp: Nutze os.getuid() um zu prüfen ob root-Rechte vorliegen — ohne root werden einige /proc/[PID]/-Einträge gesperrt. Das Tool soll trotzdem laufen und nur die lesbaren Prozesse auflisten.

Anforderungen
  • Subkommandos snapshot, diff und list sind implementiert
  • Prozesse werden direkt aus /proc gelesen (kein subprocess.run(['ps', ...]))
  • Berechtigungsfehler einzelner PIDs brechen den Scan nicht ab
  • snapshot speichert Zeitstempel und Hostname im JSON-Header
  • diff zeigt NEW / GONE / CHANGED klar unterscheidbar
  • list --sort [cpu|mem|pid|name] sortiert die Tabelle entsprechend
  • Nur stdlib — kein psutil
Akzeptanzkriterien
  1. snapshot läuft als normaler User ohne Exception durch
  2. Einen neuen Prozess starten, Snapshot machen, diff zeigt ihn unter NEW
  3. list zeigt mindestens PID, User, Name, CMD und RSS in übersichtlicher Tabelle
  4. JSON-Output von diff ist valide und enthält alle drei Kategorien als Arrays
  5. Das Tool zeigt keine PIDs die zwischen Scan und Ausgabe bereits beendet wurden (race condition sauber behandelt)
