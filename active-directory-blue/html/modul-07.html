DCSync Detection & Schutz

Cheat Sheets
Active Directory SIEM
Lernziele
  • DCSync via Event 4662 (DS-Replication-Get-Changes) erkennen
  • Replikations-Rechte via AD ACL-Audit überwachen
  • Protected Users Security Group für privilegierte Accounts nutzen
  • AD Recycle Bin für Objekt-Wiederherstellung aktivieren
Hintergrund

DCSync erzeugt Event 4662 mit spezifischen Properties: DS-Replication-Get-Changes und DS-Replication-Get-Changes-All. Diese Events sollten nur von Domain Controller-Accounts ausgelöst werden — alles andere ist verdächtig.

Protected Users Security Group ist eine eingebaute Härtungsmaßnahme: Mitglieder können kein NTLM, kein Kerberos Delegation, keine RC4-Verschlüsselung nutzen. TGTs laufen nach 4 Stunden ab. Das schützt gegen viele AD-Angriffe gleichzeitig.

Schlüsselkonzepte

Event 4662 Audit aktivieren

Code anzeigen
# AD Object Auditing muss aktiviert sein:
# GPO: Computer Config → Windows Settings → Security Settings
# → Advanced Audit Policy Configuration
# → DS Access → Audit Directory Service Access: Success, Failure

# Auf NC-Head (Default Naming Context) Audit-ACE setzen:
# Active Directory Users and Computers → View → Advanced Features
# Rechtsklick Domain → Properties → Security → Advanced
# → Auditing → Add → Principal: Everyone
# → Type: Success, Applies to: This object only
# → Permissions: Replicate Directory Changes

Protected Users Gruppe

Code anzeigen
# Privilegierte Accounts hinzufügen:
Add-ADGroupMember "Protected Users" -Members "Administrator","DomainAdmin1"

# Was Protected Users verhindert:
# - NTLM Authentication (kein PtH!)
# - Kerberos DES und RC4
# - Kerberos unconstrained delegation
# - Credentials im LSASS cached

# Vorsicht: Service Accounts NICHT hinzufügen

Test: PtH gegen Protected-Users-Account schlägt mit NTLM-Fehler fehl.

Aufgabe

Implementiere DCSync-Erkennung: aktiviere Audit auf Naming Context, erstelle SIEM-Regel für Event 4662 und füge alle Tier-0-Accounts zur Protected Users Group hinzu.

Anforderungen
  1. AD Object Auditing auf DC aktivieren
  2. SIEM-Regel: Event 4662 von Nicht-DC-Quellen
  3. DCSync simulieren → Alert verifizieren
  4. Protected Users: alle Tier-0-Accounts hinzufügen
  5. Test: PtH gegen Protected-Users-Account
Akzeptanzkriterien
  • Event 4662 bei DCSync sichtbar
  • Alert ausgelöst von Non-DC-Source
  • PtH gegen Protected Users scheitert
