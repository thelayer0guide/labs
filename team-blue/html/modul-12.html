Blue Team Abschlussprojekt — SOC-Übung

Cheat Sheets
wireshark bash linux
Lernziele
  • Vollständige Angriffs-Timeline aus Logs rekonstruieren
  • Alle erlernten Blue-Team-Techniken in einem Szenario kombinieren
  • Incident-Report nach Unternehmensstandard schreiben
  • Empfehlungen zur Verbesserung der Sicherheitsarchitektur formulieren
  • Purple-Team-Denken: Angriffs- und Verteidigungs-Perspektive verbinden
Hintergrund

In diesem Abschlussprojekt übernimmst du die Rolle des SOC-Analysten bei einem simulierten Sicherheitsvorfall. Die Herausforderung: du bekommst nur die Rohdaten — Logs, pcap, Speicherabbild — und musst daraus eine vollständige Angriffs-Story rekonstruieren.

Purple Teaming ist die Zusammenarbeit von Red und Blue Team: Red Team führt kontrollierte Angriffe durch, Blue Team versucht sie zu erkennen und blockieren. Gemeinsam verbessern sie die Detektionsfähigkeiten.

Schlüsselkonzepte

SOC-Analyse-Workflow

Code anzeigen
# 1. Alert triage
#    - Was löste den Alert aus?
#    - Ist es false positive?

# 2. Scope bestimmen
#    - Nur ein System oder mehrere?
#    - Patient Zero identifizieren
#    - Zeitfenster eingrenzen

# 3. Evidence sammeln
#    - Logs exportieren
#    - pcap sichern
#    - Speicherbild erstellen

# 4. Analyse
#    - Timeline erstellen
#    - Angriffspfad rekonstruieren
#    - IOCs extrahieren

# 5. Eindämmung
#    - Infizierte Systeme isolieren
#    - IOCs in Firewall/IDS blocken

# 6. Bericht
#    - Executive Summary
#    - Technische Details
#    - Remediation

IOC-Management

Code anzeigen
# Indicators of Compromise sammeln:
# IP-Adressen der Angreifer
# Malware-Hashes (MD5, SHA1, SHA256)
# Dateinamen/Pfade
# Registry-Keys
# C2-Domains
# User-Agent-Strings

# IOCs in STIX-Format exportieren (Standard):
import stix2, datetime

indicator = stix2.Indicator(
    name="Malicious IP",
    pattern="[ipv4-addr:value = '198.51.100.5']",
    valid_from=datetime.datetime.now(),
    labels=["malicious-activity"]
)
print(indicator.serialize(pretty=True))

Remediation-Maßnahmen

Code anzeigen
# Nach Incident:
# 1. Root-Cause dokumentieren
# 2. Angriffsvektor schließen (Patch, Konfiguration)
# 3. Backdoors entfernen (alle!)
# 4. Passwörter für kompromittierte Accounts ändern
# 5. IOCs in Monitoring-Systeme aufnehmen
# 6. Awareness-Training für betroffene Nutzer
# 7. Prozess-Verbesserungen aus Lessons Learned
# 8. Playbook aktualisieren
# 9. Retesting nach Remediation
Aufgabe

Analysiere ein vollständiges Incident-Szenario (TryHackMe "Blue" Room oder bereitgestelltes Log-Paket). Erstelle eine vollständige Angriffs-Timeline, extrahiere alle IOCs und schreibe einen professionellen Incident-Report.

Anforderungen
  1. Vollständige Angriffs-Timeline erstellt
  2. Mindestens 5 IOCs extrahiert (IPs, Hashes, Domains)
  3. Incident-Report mit Executive Summary und technischen Details
  4. Remediation-Plan für alle Findings
  5. MITRE ATT&CK-Mapping der Angriffstechniken
Akzeptanzkriterien
  • Timeline hat Zeitstempel und Quelle für jeden Schritt
  • IOCs sind reproduzierbar (mit Beweis-Screenshot)
  • Executive Summary ist ohne technisches Vorwissen verständlich
