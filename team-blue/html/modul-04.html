Network Security Monitoring

Cheat Sheets
wireshark nmap
Lernziele
  • Wireshark für Netzwerk-Analyse einsetzen
  • IDS/IPS-Grundkonzepte verstehen (Snort/Suricata)
  • Suricata-Rules für Angriffserkennung schreiben
  • NetFlow-Analyse für Anomalie-Erkennung nutzen
  • Firewall-Regeln nach Allowlist-Prinzip konfigurieren
Hintergrund

Network Security Monitoring (NSM) ist das Überwachen des Netzwerkverkehrs auf verdächtige Muster. Basis-Werkzeuge: Wireshark (Packet-Analyse), Suricata/Snort (IDS/IPS), NetFlow (Verkehrsstatistik).

IDS (Intrusion Detection System) erkennt Angriffe und alarmiert. IPS (Intrusion Prevention System) erkennt UND blockiert automatisch. Suricata ist Open-Source und kann beides — abhängig von der Konfiguration.

Schlüsselkonzepte

Wireshark-Filter

Code anzeigen
# Nur HTTP-Traffic
http

# Nur DNS-Requests
dns

# Traffic von/zu IP
ip.addr == 192.168.1.10
ip.src == 192.168.1.10

# Verdächtige Ports
tcp.port == 4444   # Metasploit Standard
tcp.port == 1337

# Große Datenübertragungen (Exfiltration?)
http.content_length > 1000000

# Alle SYN ohne SYN-ACK (Port Scan?)
tcp.flags.syn == 1 && tcp.flags.ack == 0

Suricata-Rules

Code anzeigen
# Syntax: action protocol src_ip src_port -> dst_ip dst_port (options)

# Nmap-Scan erkennen
alert tcp any any -> $HOME_NET any (msg:"Possible Nmap Scan"; flags:S; threshold:type both, track by_src, count 20, seconds 5; classtype:network-scan; sid:1000001; rev:1;)

# Reverse Shell (Netcat)
alert tcp $HOME_NET any -> any 4444 (msg:"Possible Reverse Shell on 4444"; flow:established,to_server; content:"bash -i"; classtype:shell-code; sid:1000002; rev:1;)

# DNS-Tunneling (ungewöhnlich lange DNS-Namen)
alert dns any any -> any 53 (msg:"Possible DNS Tunneling - Long Query"; dns.query; content:"."; pcre:"/^.{50}/"; classtype:bad-unknown; sid:1000003; rev:1;)

Firewall Allowlist

Code anzeigen
# iptables — Allowlist-Prinzip
# Erst alles verbieten, dann explizit erlauben

# Standard-Policy: DROP
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT DROP

# Loopback immer erlaubt
iptables -A INPUT -i lo -j ACCEPT
iptables -A OUTPUT -o lo -j ACCEPT

# Established Connections
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -m conntrack --ctstate ESTABLISHED -j ACCEPT

# SSH nur von bestimmtem Subnetz
iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 22 -j ACCEPT

# HTTP/HTTPS outbound
iptables -A OUTPUT -p tcp --dport 80 -j ACCEPT
iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT
Aufgabe

Analysiere eine bereitgestellte pcap-Datei (z.B. von malware-traffic-analysis.net) in Wireshark. Identifiziere C2-Kommunikation, laterale Bewegung oder Datenexfiltration. Schreibe eine Suricata-Regel für das gefundene Muster.

Anforderungen
  1. Wireshark-Filter für verdächtigen Traffic angewendet
  2. Mindestens ein IOC aus pcap-Datei extrahiert
  3. Suricata-Regel für gefundenes Muster geschrieben
  4. Firewall-Allowlist für Beispiel-Server konfiguriert
Akzeptanzkriterien
  • Wireshark-Filter ist korrekte Display-Filter-Syntax
  • Suricata-Regel hat korrekte Syntax (action proto src -> dst)
  • IOC ist reproduzierbar in pcap nachweisbar
