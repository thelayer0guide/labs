Email Security & Anti-Phishing

Cheat Sheets
bash
Lernziele
  • SPF, DKIM und DMARC als E-Mail-Sicherheits-Trio verstehen und konfigurieren
  • Phishing-E-Mails analysieren und Header lesen
  • Anti-Phishing-Training und Awareness-Maßnahmen planen
  • E-Mail-Gateways und Filter-Technologien kennen
  • Business Email Compromise (BEC) als Angriffsmuster verstehen
Hintergrund

90% aller Cyberangriffe beginnen mit einer Phishing-E-Mail. SPF, DKIM und DMARC sind die technischen Gegenmaßnahmen auf DNS-Ebene — sie verhindern E-Mail-Spoofing.

Business Email Compromise (BEC) kostet Unternehmen Milliarden jährlich: Angreifer kompromittieren oder fälschen die E-Mail-Adresse eines Executives und weisen Zahlungen an.

Schlüsselkonzepte

SPF, DKIM, DMARC

Code anzeigen
# SPF (Sender Policy Framework)
# DNS TXT Record: welche IPs dürfen als domain.com senden?
example.com. IN TXT "v=spf1 ip4:203.0.113.1 include:_spf.google.com ~all"
# ~all = softfail (markieren), -all = hardfail (ablehnen)

# DKIM (DomainKeys Identified Mail)
# E-Mail wird mit Private Key signiert
# Public Key im DNS-Record
# selector._domainkey.example.com. IN TXT "v=DKIM1; k=rsa; p=MIIBIjANBg..."

# DMARC (Domain-based Message Authentication)
# Richtlinie für SPF/DKIM-Fehler
example.com. IN TXT "v=DMARC1; p=reject; rua=mailto:dmarc@example.com; pct=100"
# p=none/quarantine/reject
# rua: Report-Adresse

Phishing-E-Mail analysieren

Code anzeigen
# E-Mail-Header lesen
# (In Mail-Client: "Quelltext anzeigen")

# Wichtige Header-Felder:
# From: (sichtbar für Empfänger)
# Return-Path: (echter Absender-Server)
# Received: (Hop-by-Hop Reiseroute)
# Authentication-Results: (SPF/DKIM/DMARC Ergebnis)

# Analyse:
# 1. From ≠ Return-Path → Spoofing-Versuch
# 2. Authentication-Results: dmarc=fail → Spoofing
# 3. Received: von unbekanntem Server → verdächtig
# 4. URL-Hover: zeigt anderes Ziel als Linktext

# Online-Tools:
# MXToolbox: https://mxtoolbox.com/
# Mail-Tester: https://www.mail-tester.com/

Link-Analyse

Code anzeigen
# URLs in E-Mails prüfen
# Direkt nie klicken — kopieren und analysieren!

# DNS-Lookup
dig suspicious-domain.ru A
whois suspicious-domain.ru

# VirusTotal
curl -s "https://www.virustotal.com/vtapi/v2/url/scan" \
  -d apikey=KEY -d url="https://suspicious.com"

# URLScan.io
curl -s "https://urlscan.io/api/v1/scan/" \
  -H "API-Key: KEY" -H "Content-Type: application/json" \
  -d '{"url":"https://suspicious.com","visibility":"private"}'
Aufgabe

Prüfe die E-Mail-Sicherheitskonfiguration einer eigenen Domain (oder testdomain.com) mit MXToolbox: SPF, DKIM und DMARC vorhanden? Analysiere eine Phishing-E-Mail (Beispiel-Sample online verfügbar) auf Header-Ebene.

Anforderungen
  1. SPF-Record für Testdomain korrekt interpretiert
  2. DMARC-Policy erklärt (none vs. quarantine vs. reject)
  3. Phishing-Header analysiert (Spoofing erkannt)
  4. Mindestens 3 Phishing-Indikatoren identifiziert
Akzeptanzkriterien
  • MXToolbox zeigt SPF, DKIM, DMARC Status
  • Header-Analyse zeigt Return-Path ≠ From
  • Phishing-Indikatoren sind reproduzierbar benannt
