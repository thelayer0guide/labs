Modul 07 Hardening & Prevention 3–4 h ★★★★★ Fortgeschritten

Windows Server Hardening

Cheat Sheets
powershell
Lernziele
  • Windows Server Baseline Security konfigurieren
  • Group Policy Objects (GPO) für Security-Einstellungen nutzen
  • Windows Defender Einstellungen optimieren
  • SMB-Signing und LDAP-Signing aktivieren
  • Windows Audit-Richtlinien für Logging konfigurieren
Hintergrund

Windows-Umgebungen sind das häufigste Angriffsziel in Unternehmen — aus gutem Grund: sie dominieren Enterprise-Umgebungen. Richtig konfiguriert sind sie aber sehr sicher.

Group Policy ist das zentrale Verwaltungswerkzeug für Windows-Sicherheit. Eine einzige GPO kann hunderte Sicherheitseinstellungen auf tausende Computer gleichzeitig anwenden.

Schlüsselkonzepte

PowerShell Hardening-Checks

Code anzeigen
# Defender-Status
Get-MpComputerStatus
Get-MpPreference

# Audit-Richtlinien
auditpol /get /category:*

# Aktivierte User-Accounts
Get-LocalUser | Where-Object {$_.Enabled -eq $true}

# Admin-Gruppe Mitglieder
Get-LocalGroupMember -Group "Administrators"

# SMB-Konfiguration
Get-SmbServerConfiguration | Select EnableSMB1Protocol, RequireSecuritySignature

# Offene Shares
Get-SmbShare
Get-SmbShare | Where-Object {$_.Name -ne "ADMIN$" -and $_.Name -ne "C$" -and $_.Name -ne "IPC$"}

Wichtige GPO-Einstellungen

Code anzeigen
# Passwort-Richtlinien:
# Computer Config > Windows Settings > Security Settings > Account Policies
# Min. Länge: 14 Zeichen
# Komplexität: aktiviert
# Max. Alter: 90 Tage

# Audit-Richtlinien:
# Logon Events: Erfolg + Fehler
# Account Management: Erfolg + Fehler
# Process Creation: Erfolg
# Privileged Use: Erfolg + Fehler

# PowerShell via GPO:
auditpol /set /subcategory:"Logon" /success:enable /failure:enable
auditpol /set /subcategory:"Process Creation" /success:enable

SMB und LDAP Signing

Code anzeigen
# SMB-Signing (verhindert NTLM-Relay-Angriffe)
Set-SmbServerConfiguration -RequireSecuritySignature $True -Force

# SMBv1 deaktivieren (EternalBlue!)
Set-SmbServerConfiguration -EnableSMB1Protocol $False -Force

# LDAP-Signing (Domain Controller)
# GPO: Default Domain Controller Policy
# Computer Config > Policies > Windows Settings > Security Settings
# > Local Policies > Security Options
# Domain Controller: LDAP server signing requirements → Require signing
Aufgabe

Konfiguriere einen Windows-Server (oder Windows 10/11 VM) nach CIS Benchmark Level 1. Deaktiviere SMBv1, aktiviere SMB-Signing, konfiguriere Audit-Richtlinien und prüfe Defender-Status.

Anforderungen
  1. SMBv1 deaktiviert
  2. SMB-Signing aktiviert
  3. Audit-Richtlinien für Logon und Process Creation aktiviert
  4. Defender läuft mit aktuellen Signaturen
  5. Administrator-Account umbenannt
Akzeptanzkriterien
  • Get-SmbServerConfiguration zeigt EnableSMB1Protocol=False
  • Auditpol zeigt Logon Success+Failure aktiv
  • Defender Real-Time-Protection ist On
